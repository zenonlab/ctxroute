# deploy.js / deployed-scan.js / deploy-pure.js — reconciles production FROM the working tree

⚠️ REASON TO EXIST: `tools/doctor.js --deployed <dir>` already SAYS whether the deployed copy diverges from this repository (`deployedDriftVerdict`). It never RECONCILES — reading a drift and copying the files by hand is manual toil, and manual toil is exactly what this project exists to eliminate. `npm run deploy -- --deployed <dir>` is the geste that closes the loop.
🛑 THE SHELL (`tools/deploy.js`) DECIDES NOTHING. Every branch — refuse / do nothing / copy — is decided by `src/deploy-pure.js`, a PURE module (zero `fs`/`path`/`child_process`, Stryker-mutated, sealed by `deploy-pure-must-stay-pure`). The shell only MEASURES three facts (`git status --porcelain`, the fast test suite's exit code, the deployed-drift verdict), calls `planDeploy`, and EXECUTES its plan. A decision written in the shell would sit outside Stryker's reach — the fleet's worst defect class, a green gate that sees nothing.
⚠️ **THE SCAN IS SHARED, NOT DUPLICATED**: `src/deployed-scan.js` (`git ls-files src` + the paired repo/deployed hashing, line endings normalised before hashing) is the SAME module `tools/doctor.js --deployed` uses. Extracted 2026-09-03 out of `doctor.js`'s `checkDeployed()` for exactly this reason — two copies of that reading would be two truths that diverge, the exact class this repo fights everywhere else.
⚠️ **THREE NAMED OUTCOMES, `src/deploy-pure.js`'s `planDeploy({dirtyPaths, suiteOk, verdict})`**: `refuse` (dirty tree, red suite, or an `unmeasured` verdict — "I could not measure" is never "it is healthy") · `nothing` (`match`) · `copy` (`drift`, carrying the EXACT drifted paths, never "copy everything"). ⚠️ ORDER IS DELIBERATE: a dirty tree is checked BEFORE the suite result — what would be copied is not what was tested, so the suite result is untrustworthy on a dirty tree anyway, and refusing on the cheaper fact first means the suite never pays for a run nobody can trust.
🛑 **`npm test` CANNOT BE SPAWNED WITHOUT `shell: true` ON WINDOWS** (MEASURED 2026-09-03: `spawnSync('npm', …)` → ENOENT on the bare name, EINVAL on the resolved `.cmd` shim — a known Node limitation on `.cmd`/`.bat` files). `shell: true` is FORBIDDEN FOR ALL LAYERS here (`layers.json`). `tools/deploy.js` therefore reads `package.json`'s OWN `scripts.test` (never hardcoded — stays in sync with the repo's real definition of "the fast suite" by construction), resolves its first word to the LOCAL package's declared `bin` entry file (e.g. `vitest` → `node_modules/vitest/vitest.mjs`), and runs it with `node` DIRECTLY — the same "call the tool by its path, never by its name" rule the mutation doctrine already applies to Stryker. NEVER reintroduce `shell: true` to "fix" this.
⚠️ **ENDS BY RE-RUNNING THE JUDGE**: after a successful reconciliation (or when nothing needed copying), it re-invokes `doctor.js --deployed <dir>` and requires exit 0. A copy that leaves the judge red did not actually reconcile anything — delivering beats declaring victory.
⚠️ **`--deployed` IS REQUIRED HERE**, unlike the doctor's opt-in flag (a deploy with nothing to deploy TO is meaningless), parsed by the SAME `deployedArgument`/`DEPLOYED_FLAG` as `doctor-wiring-pure.js` — one parser, one refusal vocabulary (relative path / declared twice / no value at all), never a second copy that drifts.
⚠️ **`CTXROUTE_REPO_DIR` IS A TEST-ONLY OVERRIDE** (same convention as `paths.js`'s `CTXROUTE_CONFIG_PATH`), read by BOTH `tools/deploy.js` and `tools/doctor.js` — a spawned child inherits it by default, so ONE env var drives the whole reconciliation (scan AND the final re-run of the judge) against a throwaway fake repo instead of the real checkout. `test/deploy.test.js` is the behavioural proof: a real `git init` repo in a tmpdir, its own controllable `test` script (`node -e process.exit(N)` — never `npm test`, which would recurse and depend on devDependencies a tmpdir does not have), the real `tools/deploy.js` spawned against it.
🛑 SCOPE STAYS `src/` ONLY, same as the doctor's `--deployed`. Deploying anything outside `src/`, remote deployment, rollback, and `settings.json` wiring are OUT OF SCOPE — a different work item, never a silent scope creep of this one.
