# emission-core.js — THE LAYER EVERY EMITTER GOES THROUGH (2026-08-05)
⚠️ **NO EMITTER COMPOSES ITS OWN OUTPUT** — it returns segments to this layer (the web-framework pattern: a handler never serializes its response). Writing `additionalContext` without going through here = silent spill as soon as the content exceeds the frame. That is the EXACT defect that left `session-inject.js` without transport for weeks: transport was a CALLER'S CHOICE, hence opt-in by copy-paste.
⚠️ **THE LAYER IS NOT ENOUGH, THE GATE MAKES IT MANDATORY**: `emission-core-gate.test.js` scans the files that write the `additionalContext` key and requires that they REACH this module (TRANSITIVE traversal — the shells go through `pretool-core.js`, forcing a direct import on them would break the layers). **DERIVED from the code, never a list** ⇒ every FUTURE emitter is covered the day it is written. NEVER replace it with a hard-coded list: it would depend on vigilance, which is exactly what we are fixing.
⚠️ **THIS FILE IS AN I/O SHELL** (queue store) — never Stryker-mutated. ALL the transport decision is PURE and lives in `budget.js` (`orderSegments`, `planFrames`, `baseId`), mutated at 100 %. NEVER bring logic back here: read the queue → delegate → rewrite the queue, nothing else.
⚠️ **QUEUE SHARED BY ALL EMITTERS, DELIBERATELY.** At SessionStart there is no "next action" to drain into: it is the COMMON store (same `remainder-` prefix, same agent scope) that makes the session gate's leftover be picked up by the PreToolUse gate on the very first tool call. NEVER prefix the queue per emitter — that would make the session leftover undrainable.
⚠️ **`emettre` IS CALLED UNDER LOCK** (it reads then rewrites the queue). Lock unavailable ⇒ degrade to `decouper` (fresh only, queue INTACT) — never go silent, never write without the lock. `decouper` alone is reserved for REPLAYS of an already decided split (memoized plan) and for that degraded path.
⚠️ **WE DO NOT MERGE THE EMITTERS**: SessionStart and PreToolUse have DIFFERENT events and output contracts. We share the EMISSION LAYER, never the orchestration.
⚠️ **EMISSION COUNTER (2026-08-07) = the canary's DENOMINATOR.** `emettre` increments `emissions` in the `remainder-` store **only if `segments` is non-empty** (counting empty passes would accuse a non-existent outage), and it travels in the write that ALREADY existed ⇒ zero I/O, zero extra lock. 🛑 It exists because the Codex doc says the transcript format *"isn't a stable interface"*: the canary therefore CANNOT count tool calls at the harness. Absent key = 0 (backward compatible). **Changing the prefix, the key or the scope would make the canary mute and green FOREVER** — sealed by the "BOUNDARY CONTRACT" test of `canary-check.test.js`.
⚠️ **EXEMPTION = RELIC ONLY**, declared with its WHY in the gate, and the INVERSE part kills it as soon as it is stale. NEVER list a LIVE emitter there.
