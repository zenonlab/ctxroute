## 🔒 PUBLIC REPOSITORY: A RED SUITE NEVER SHIPS — OPERATOR RULE
🛑 Nothing reaches the public remote while `npm run test:all` is red. Decidable by ONE question, never "is this important": **is the repository PUBLIC?** Private ⇒ pushing without the full suite is allowed (velocity wins, a bad push costs only a fix). Public ⇒ forbidden — a published history cannot be taken back.
✅ One exception: a commit whose ONLY content is the fix for the current red MAY ship while that red stands (never a licence to ride other changes along). Disappears the day a private CI-before-publish exists.
⇒ Enforced SERVER-SIDE (GitHub branch protection, required checks `test`+`coupling` only — never `mutation`/`service-units`, too slow to survive), armed only once the CI is green. Publishing form: push a branch → wait for checks → merge; the direct `commit-tree` push stops working, on purpose. Full incident history: `engine-history-reference.md`.

## 🔴 ANOTHER OS IS ONE COMMAND AWAY — NEVER CONCLUDE "OUT OF REACH OF THIS SESSION"
🛑 All four workflows carry `workflow_dispatch`: a Linux/macOS verdict is `gh workflow run <workflow>.yml` on the ref you choose — deploys nothing, pushes nothing, needs no throwaway branch. ⚠️ Dispatch needs a token with `Actions: write`; a contents-only token gets HTTP 403 (measured 2026-09-23). Then the verdict still exists: push the current TREE as ONE commit (`git commit-tree`, local history never published) to a `ci-probe-*` branch whose tree alone adds that branch to `test.yml`'s `push.branches`, read the three jobs (`fail-fast: false`), delete the branch. Being on Windows is never a reason to skip Linux or macOS. The ONLY sentence that may replace a verdict is a MEASURED blocker (a command and its output), never "impossible"/"later"/"untestable from here". A macOS runner bills ×10 Actions minutes (Windows ×2, Linux ×1) — a dispatch is a gesture you choose, but choosing not to is a decision you WRITE DOWN. 0septies. 🛑 **WHEN IS A DEFECT CLASS ACTUALLY CLOSED? FOUR CONDITIONS, ALL NECESSARY.** Apply to every guardrail you write or inherit — missing ONE makes it a note, not a gate.

## THE VOCABULARY — a closed boolean base, one word per concept, never a synonym
1. **What this is**: a declarative language (DSL) for TRACEABLE context-injection workflows. You DESCRIBE when knowledge must appear; the machine injects it, predictable and explainable.
2. **Single primitive**: DECIDABLE event → injection. The engine's SOURCES are exactly the `source-adapters.js` registry ids: `file` · `mcp` · `skill` · `tool`. Extending = 1 pure source + 1 adapter, the core never moves.
2bis. `docs/session/` is NOT a source — `session-inject.js` delivers it once per context (SessionStart/PostCompact), consulting no cadence; setting one is accepted and has no effect.
2ter. **Ambition = multi-harness industry standard**: pure engine with no dialect (CI-gated) + shared cores (`pretool-core`/`guard-core`) + thin shells per harness (~15 lines of emit). New harness = measure its dialect first (doc-first + a real captured payload), reuse gates if identical, else write a shell — never a copy, never a harness-`if` in the core.
3. **Matching = a CLOSED BOOLEAN BASE**: `match` = OR (at least one pattern present) · `scope` = AND between axes, two forms (`["a","b"]` = OR, `[["a"],["b"]]` = AND of ORs, mixed REFUSED) · `exclude` = ∀¬ over ALL params ∪ the triggering context (a true "for all", never evaluated per-candidate — a per-candidate negation is bypassable by how an action is phrased). We never add a 4th connective: the base is closed, a new word would be a synonym (anti-synonym law, precedent `perimeter` deleted). Exact expressiveness (`language-completeness.test.js`): 128/256 conditions, characterized as `{f | f(empty action)=false}` — complete up to the one structural wall "nothing injects on nothing" (§3bis, a feature not a hole).
3bis. **Load-bearing wall: decidable, NEVER heuristic.** We only inject on FACTS (tool called, file touched, perimeter crossed) — never guess intent, zero embeddings. The action is a perfect, decidable proxy of intent; you can always answer "why did this inject?".
3ter. **`keys` — WHERE to look, orthogonal to WHAT to look for.** Two forms: `["-name"]` REMOVES from the default universe (per-axis or shared: `["-command"]` for all three, or `{match:[...], scope:[...], exclude:[...]}` per axis) · bare names REPLACE it (may WIDEN, reading a key the profile never declared). A mixed form (some `-`, some bare) is ADMITTED: at least one `-` ⇒ ADJUST, no `-` ⇒ REPLACE. What is refused is the AMBIGUOUS (half whitelist/half blacklist expresses nothing decidable), never the unusual. Three derived, session-carrying facts of a shell gesture live in a REGISTRY (`src/derived-observables.js`), never as scalar fields: `command` (the raw text) · `commandCwd` (the `cd X && …` directory) · `commandPaths` (paths RECONSTRUCTED by gluing that directory to every following word). A project entry that wants "citing it stops injecting, working in it still does" writes `keys: {match:["-command","-commandPaths"]}` — dropping only `commandCwd` changes nothing, since the directory is a PREFIX of every reconstructed path. `defaults.{file|mcp|skill|tool}` carries `scope`/`exclude`/`keys` TOGETHER (never `match`, the only operator that CREATES an injection — a category-wide trigger would fabricate rules for entries declaring none); the entry always wins entirely, never a merge. Absent from MCP docs, with a written reason: they carry no matching operator (path-triggered), so `keys` would be accepted and inert. Full ten-defect delivery history and every measured divergence count: `engine-history-reference.md`.
4. **Not Turing-complete, ON PURPOSE**: the parallel is SQL/CSS/a routing table, never bash. We never ship one grain less than the grammar allows; the uncrossable wall is arbitrary computation/heuristics.
5. **Cadence = ONE axis** "re-inject after N ticks": `dumb`=0 · `smart`=N · `once`=∞ (compaction is the only true emptying; in between = dilution). `driftUnit` (`tool`|`turn`) is the tick's unit, degenerate outside `smart`. Guardrail → `dumb`, project knowledge → `once`, `smart` = a middle to use sparingly.
5bis. **AGENT DOCTRINE = CONTEXT**: master and EACH sub-agent are totally distinct contexts ⇒ distinct injection state per agent. Store key = `lib.scopeId(session_id, agent_id)` — NEVER `session_id` alone (shared master/sub-agents by harness contract on both Claude Code and Codex ≥0.146.0; without `agent_id` = the historical, session-only key, for backward compat). Founding hole (closed): keyed on session alone, sub-agents never received `once` skills, consumed by the master.
6. **Config = ownership**: frontmatter ONLY in what we control 100% (our docs); a HARNESS file (skill, server) → registry in OUR JSON. Condition for cross-harness portability.
7. **The 4 AUTHORITIES, everywhere, no exception** (`mode`/`threshold`/`driftUnit`, and every future cascaded setting): ① framework default hardcoded (exists with no JSON) > ② global config (JSON) > ③ `defaults.{source}` (one category — `file`/`mcp`/`skill`/`tool`) > ④ entry (frontmatter/registry) = last word. TOTAL fallback at every stage, SINGLE resolution point = `gate.js` — **a source POSES the entry, it never resolves** (invariant: empty entry ⇒ EMPTY decl, sealed by `declfor-gate`'s five checks, both directions: filtering a declared key and filling an absent one are both silent-stage-killers). Only deliberate asymmetry: `skill` skips stage ② (framework default `once`, docs `smart`).
7bis. **Symmetry by DEFAULT, exception DECLARED**: every behaviour key lives in the 4 corpora (file doc · MCP doc · skill entry · `defaults.{source}`) — a gap must be justified in writing or `frontmatter.test.js` reddens (inverse check included: a stale justification reddens too).
8. **Growth = enriching the VOCABULARY, never arbitrary computation.** ⚠️ **ONE CONCEPT = ONE WORD, EVERYWHERE (anti-synonym law)**: before adding a key, check whether an existing primitive already covers the semantics. The full vocabulary today: `match`/`mcp`/`rules`/`tool`/`category`/`response`/`scope`/`exclude`/`mode`/`threshold`/`driftUnit`/`note`/`enforce`, no exception.
   - **`category`** (Phase 1) = string or list, joins `enforce`/`filterMode`'s family — NEVER a trigger, it NARROWS an injection another trigger already selected. Absent = universal (parity). Matches against categories DECLARED for the SESSION (a fact `ctxroute` itself owns via `src/category-store-pure.js`, no harness exposes it) — no session category ⇒ every categorized doc excluded, fail-closed. 2-stage cascade like `enforce` (entry > `defaults.{source}`, no global). READ-side only in this repo: the mechanism that SETS a session's category is an opinion, lives in `ctxroute-policies`. Detail: `category.md`.
   - **`response`** (23/09/2026) = inline JSON `{"scope":[…],"exclude":[…]}` — the only word that reads what the tool ANSWERED instead of what the agent sent. A SETTING (registry, gate.js), never a trigger nor a `rules`-entry key: the doc is decided AFTER the action (`gate.decide`'s 9th arg), only if the answer satisfies it. One action = two moments, each doc in exactly one; after the answer NO drift tick and NO refusal (`enforce: true` + `response` refused). Never reached through `keys` (a parameter named `response` would collide — the STRUCTURE separates them). The after moment has its OWN invocation id and its OWN bandwidth (`afterFrames`). Detail: `response.md`. 🛑 **OFF BY DEFAULT (`afterFrames` absent or 0) and NOT recommended on Claude Code** (operator decision 2026-09-23): measured +20-30 ms and extra status lines per tool call, for no gain until a real `response` doc exists; Codex (command lane) keeps it.
   - **`enforce`** = boolean, REFUSES the action (`enforce: true` ⇒ `deny`); an explicit `false` CANCELS inheritance from `defaults.{source}` (without it a category switched to enforce would be impossible to opt out of). NO global stage (a global block would refuse the first action of every session). `ask`/`confirm` are REMOVED and permanently forbidden (human escalation = anti-0-human, absent from Codex).
   - **`note`** = author comment, the ONLY field the engine NEVER reads — invisible to injection since the whole frontmatter is stripped. Never the why of an INVARIANT (that stays in the body).
   - The 4 TRIGGERS, disjoint semantics, never merged: `match` = PATH substring · `mcp` = exact SERVER name · `rules` = per-entry match · `tool` = EXACT name of a native TOOL (the blind spot of tools with no path and no `mcp__` — WebFetch/WebSearch — closed; a future harness tool needs zero code, naming it in a doc is enough).
9. **Honest**: covers 100% of the decidable-that-acts; "finding the unknown" stays with RAG. Ultimate goal: eliminate toil — learn once, never re-explain. Work is one-time capex, the asset is eternal.

## EXTENSION CONTRACT (invariants of ANY new primitive/source)
1. **UNIQUE vocabulary**: reuse `match`/`scope`/`exclude`/`mode`/`threshold`/`driftUnit` — never a synonym.
2. **ALL grains, from day one**: a dimension ships COMPLETE (e.g. MCP = server AND tool AND sub-tool) — one grain less betrays the language.
3. **4-authority cascade** on every setting, total fallback at every stage — never fewer stages. A source POSES, it never resolves (empty entry ⇒ empty decl). The signature stays `declFor(fm)` — frontmatter only, never `config`, or the double resolution reopens.
4. **MECHANICAL injection of the knowledge itself** (body read live from its single source), never a pointer hoping the agent obeys.
5. **Schema FIRST**, then a PURE source + adapter (the core never moves), mirrors (`mutate`/`includeOnly`/`mutation.yml`/dep-cruiser), re-mutation 100%, doctor probe + negative-check, injectable doc + skill (FILE-MAP entry).
6. **Default behavior = the PREVIOUS behavior, identical** — differentials stay green with no edit.
7. **UNIVERSALITY OF SIGNALS**: base matching ONLY on what EVERY harness exposes BY NECESSITY (paths, commands, MCP tool names). Never an optional harness metadata as the sole trigger — an optional signal is a perimeter that dies silently on a harness that omits it. `cwd` is the counter-example, proven universal by doc-first measurement (a common field of both harnesses' hook contracts) — the lesson is "measure universality before refusing", not "cwd is forbidden".
8. **THE KNOB TEST**: "can the existing data (patterns/scope/exclude) already express the distinction?" YES ⇒ nothing to add (precedent: `cwd` became a plain matchable param, no new word). NO ⇒ one vocabulary word, full 4-authority cascade (precedent: `driftUnit`). Measure the real case FIRST, never preventively.
9. **ONE DECLARATION PER FACT — the registries (23/09/2026)**: a new SETTING (a behaviour key that cascades: `mode`/`threshold`/`driftUnit`/`enforce`/`category`) = ONE entry in `frontmatter.settingRegistry()` (form, stage value, global key per source, framework default) + its shape in the schema's `definitions.cadence` (the skill entry `$ref`s it) + its model in `cadence-spec.js` + its tests. KNOWN (`knownKeys()`), the MCP keys, the form validation, both sources' `declFor` (`poseSettings`) and gate.js's ONE cascade (`resolveSetting`) DERIVE from it. A new per-scope STORE = ONE line in `memory-store-pure.stateStores()` (prefix, lock class, lifetime): lock routing, PreCompact purge and disk eviction derive from it. A new per-rule MATCHING operator = its name in `RULE_KEYS` + its form in `frontmatter.operatorForms()` (shared by the flat frontmatter and every `rules` entry) + its inheritance in `file.inheritFilters` + its semantics in the engine and in `language-spec.js`: the vocabulary list and the skills' match dimension derive. A new MUTATED module = `mutate` + its suite in the Stryker `include` + `includeOnly`, then `node tools/mutation-scope.js --write` (workflow paths and purity rule are generated). 🛑 The independent models (`language-spec.js`/`cadence-spec.js`) NEVER read a registry — a judge reading the engine's data agrees with it by construction. ## Porting the framework to a NEW HARNESS — strict contract
The proof starts at the adopter's: published `HARNESS-CONTRACT.md` + `node tools/doctor.js --harness <payload.json>` on a REAL payload ⇒ `supported`/`degraded`/`incompatible`. The public language reference is `LANGUAGE.md` (derived AUTO blocks, never copied). The engine is portable BY CONSTRUCTION (`sources-must-not-know-the-harness`, checks IMPORTS AND literals).
1. **ABSOLUTELY FORBIDDEN**: modifying `src/sources/`, `gate.js`, `frontmatter.js`, `loader.js`, `lib-pure.js`, `collisions.js` for a port — wrong layer, stop.
1bis. **Detect by SHAPE, never by name-list.** A shell is recognized by the PRESENCE of a `command` param, never a tool-name enumeration (born stale, fails silently). Path keys are never guessed by name (`path`/`file`/`dir` is an anglophone convention, silently blind to other languages) — what `match` cannot reach is targeted with `tool`+`scope`, never a guess.
2. **What to write, per event — NEVER a copy**: gate bodies live in shared cores (`pretool-core.js` = PreToolUse, `guard-core.js` = PostToolUse); a shell = stdin + the dialect's `emit` (~15-50 lines). Check whether the existing gate wires AS-IS first. Missing capability = EXPLICIT degradation commented in the emit, never silent.
3. **Every shell**: arms `deadline.arm()` before any I/O, fully fail-open (error = silent exit 0), paths via `paths.js` only, decisions via the pure modules only, and PRINTS only through `src/stdout-exit.js` (`printThenExit`; `exitUnlessPrinting` on a path that may have printed) — `process.exit` cuts stdout AND stderr at 64 KB on a POSIX pipe (measured 2026-10-01, invisible on Windows). Same law for EVERY entry point of `src/`/`tools/`/`service/`: a file that writes a stream leaves with `return exitAfterFlush(code)` or `process.exitCode = code; return;`, never `process.exit` (gate `stdout-exit-gate.test.js`, rule ②).
4. **MANDATORY proofs before wiring**: integration suite by real spawn on a tmpdir corpus + doctor extension (a probe per new gate + wiring check + a negative-check that SABOTAGES a copy and demands the scream).
5. A harness WITHOUT an event = skip that path and note it, never a bodged workaround.
6. Done = `npm test` green + mutation green + doctor green on the real wiring + journal/skill updated.

## 🛑 WHAT THIS FRAMEWORK CAN AND CANNOT GUARANTEE — settled 2026-08-30, never re-litigate
**ROUTING IS GUARANTEED (100% deterministic, proven on 400,000+ exhaustive cases). TRANSPORT IS NOT, AND CANNOT BE — BY ANYONE, EVER** (Two Generals Problem: no protocol over a lossy channel can guarantee arrival). The reachable guarantee is *the agent never works without the knowledge it is owed* (`enforce`⇒`deny` stops the NEXT action on a closed-incomplete invocation) — never *never lose a frame*. Never sell "nothing is ever lost"; say *routing is exact, transport can drop, and we detect it*. A silent drop would kill this project; a detected one will not.
🔒 **ONE INJECTION WINDOW PER TOOL CALL.** The harness is the CLIENT, the daemon is the SERVER — no retry exists inside one action, on any harness, by any release. An action's capacity is fixed at `frames that arrived × 10,000c`; the rest reaches the NEXT action at best. **The loss is no longer permanent** (`carryover-pure.js`): an invocation harvests the not-yet-served segments of other pending invocations of its scope and carries them itself — ownership MOVES, never shared, atomic because the daemon is single-threaded.
**The most reliable configuration is a PAIR**: one single `command` declaration + a harness with NO output cap. Codex satisfies both (`additionalContextLimit=0` removes the transport-defect class by construction, ~330ms process start). Claude Code does NOT (~10,000c cap per output ⇒ N declarations stay required, `http` lane's burst comes with them — never read "one declaration" as advice for Claude Code). Reliability is a property of the DEPLOYMENT, not of the framework.
Full incident history (loopback saga, the residual ECONNREFUSED, the connection burst, every measurement and dead end): `transport-reliability-reference.md`.
🔒 **`read ECONNRESET` ON THE HTTP LANE IS CLOSED — THE PROJECT IS NOT RESPONSIBLE (operator decision, 2026-09-24).** Measured on two kernel traces: the Windows TCP stack itself (`pid=0`) aborts the harness's connection (event 1046 *retransmission timeout*, then RST), both ends receive the RST within 2 ms, and the daemon was idle, waiting for a body that never came (`socket-cut`). A server cannot retry a request it never received; only the client can, and Claude Code's HTTP hooks do not (its other connections do) — upstream: anthropics/claude-code#96657. The environment (machine load, network state) is not this project's job: no application controls its environment. 🛑 **FINAL, NOTHING REOPENS IT: the KM-TEST adapter is the only viable choice (127.0.0.1 measured worse — refusals without SYN retry; a named pipe is impossible for HTTP hooks; the `command` lane was rejected by the operator), so no measurement could lead to an action on our side.** Never reopen on a red line, a hunch, a bench or "try 127.0.0.1". Detail: `adapter-windows.md`.

## MULTI-FRAME TRANSPORT — the framework DELIVERS EVERYTHING
**Two paths, and a third that closes everything**: ① it fits in the frame ⇒ emit as-is (zero cost) ② it doesn't ⇒ split into chunks over N frames ③ it STILL overflows ⇒ QUEUE, re-emitted at the next action — no longer a delivery ceiling, only a THROUGHPUT setting. **On ALL paths, undeliverability is now impossible** — a doc of any size arrives. Never reintroduce a size cap or "split your doc": that would make the doc's AUTHOR carry a transport defect.
`frames` = the bandwidth of one action (32 today, tunable) — raising it buys CAPACITY, never speed (the gain comes from the transport: the `http` lane measured 5,300ms → 182ms per action at the same frame count). A capacity alarm names the setting the moment a doc is deferred (once per action, last frame only). The plan is MEMOIZED per invocation so N parallel frame-processes never double-consume a `once` doc — determinism replaces coordination. Three joint guardrails keep the emission queue from looping forever: the announcement counts documents (5 max, deduped); a progress guarantee forces ONE chunk out even under pressure (delivering beats describing); the chunk header itself yields before the content does.
Protocol grounded in RFC 2046 (`message/partial`) and RFC 6455 (WebSocket): a chunk id carries `#j/m`, a common `###END:xxxx###` marker anchors reassembly, order is never interleaved. `[source: <path>]` is a CONTRACT, not decoration — an agent reads that exact path to update the doc when it's wrong, which is what makes the corpus self-repairing.
Full protocol rationale, bandwidth history, and every closed transport defect: `budget-frames-reference.md`, `http-lane-reference.md`, `transport-reliability-reference.md`.

## CANARY — the only witness watching the OTHER END of the pipe
Everything else here tests itself (the doctor spawns OUR hook with OUR payload). The canary (`canary.js` PURE + `canary-check.js` shell, UserPromptSubmit) decides `alive`/`dead`/`undecidable` on: *we emitted N times, did it ARRIVE?* — DECIDABLE via a `[source: …]` trace in the transcript; we never compare received vs expected. The denominator is OUR OWN emission counter; the search is for OUR OWN `[source:` substring — zero harness dialect, one shell for every product. Silent when healthy (a permanent alarm becomes wallpaper); threshold = 25 emissions as a sample size, reading bounded to 2MB from the transcript's end. The alarm never rides the tested pipe (an injection would die with what it reports) — output is `state/canary.json`, read by a displayer OUTSIDE the framework. The framework neither ships nor depends on any displayer.
Full incident history (the self-contradiction found by grep, the ㉘ false-green defect): `transport-reliability-reference.md`.

## Triggering on an ACTION (a command), not a PLACE — the recipe
The founding use case is an ACTION (a payment click), but the vocabulary exposes PLACES by default:
```yaml
tool: ["*"]                                  # WHO acts — `*` = ANY tool
scope: ["docker run", "systemctl enable"]    # WHAT IT DOES (scope sees ALL params, any depth)
```
`match` is useless here (paths + POSIX shell command only). `scope` is the only operator that sees ALL parameters, at ANY nesting depth (recursively flattened, bounded at 20 levels/262,144c, truncation stated by `explain.js`) — but it never triggers alone, hence the `tool:` wildcard opening the door. Wildcard WITHOUT `scope` or `exclude` is RED (would inject on every tool call — a truly universal doc belongs in `docs/session/`). Check with `node tools/explain.js --doc <name> --tool X --input '{...}'` — never a homemade probe harness, it will get the format wrong.

## Mechanism invariants
- **0-HUMAN everywhere**: the machine decides the DECIDABLE (fail-closed gates), an agent decides the HEURISTIC (on-demand), the human never in the loop.
- **THREE decisions, never four**: `none`·`allow`·`deny`. Injection informs by default; `enforce: true` is the declared exception that refuses the action (a PreToolUse's `additionalContext` arrives next to the tool RESULT — an injection cannot prevent the action it targets, only the next one; only `deny` does that). `ask`/`confirm` are PERMANENTLY removed (anti-0-human). This is a GUARDRAIL, not security — fail-open, protects from a distracted agent, never an adversary.
- **ANTI-LOOP = ALTERNATION**: a refusal is never followed by a refusal for the SAME ACTION (never per-document — two `enforce` docs in antiphase would otherwise refuse forever, each honouring "never twice in a row" alone). No mode is forbidden; `enforce` follows the cadence.
- **`doc-write-guard`** (PostToolUse) blocks on an invalid doc — a write corrector, not an action blocker.
- **One truth, one place**: a doc carries its knowledge AND cadence (frontmatter); the JSON is global/user only.
- **Frontmatter ONLY in what we control 100%**: our own docs, yes; a harness file (skill, MCP server registration) → OUR global JSON, referenced by name — cross-harness portability forbids config living in a third party's file.
- **Skill by perimeter = the 4th trigger** (`config.skills`): auto-injects the WHOLE body, read live from the harness's skills folder (never copied), on file (`match`/`scope`/`exclude`/`rules`) OR MCP (`servers`, 3 grains) OR tool (`tool`, exact name + wildcard) — 3 dimensions, reused in union, full docs↔skills parity. Pointer fallback only if the file is unreadable.
- **A file's location = its trigger**: frontmatter `rules:` (file) · path `docs/mcp/` (server) · folder `docs/session/` (every session + post-compaction).
- PreCompact reset is ABSOLUTE, mode-independent — compaction empties the real context, every per-scope store restarts from zero.
- An MCP server without `docs/mcp/{server}.md` triggers nothing (no error, no noise).
- **Fail-open hooks, screaming diagnostics** — opposite roles, never merged.
- **Frozen engine, stacking sources**: any extension is a pure module + adapter/shell, never a core modification.

## Quality — gates (`npm run check:all` before any substantial commit)
- **Tests, THREE LEVELS, never climb higher than needed**: `npm run t -- <file>` (module-graph-derived, the default while working) · `npm test` (fast lane, every edit) · `npm run test:all` (everything, locally, once per work session). Lane classification is DERIVED from content (spawn/env-mutation ⇒ heavy lane) — a new suite lands in the right box by itself.
- **Stryker mutation**: `npm run test:mutation`, mutates every pure module (I/O never mutated — isolate the decision before mutating). Break 99%, per-file floor 100% (an average threshold is blind to one collapsing file). A survivor is KILLED (targeted test) or ELIMINATED (dead code removed), NEVER waved through by lowering a threshold.
- **`.githooks/`** holds the repo's two BLOCKING gates (`pre-commit` anti-leak, `commit-msg`) — the one deliberate exception to "gates never block", because the damage avoided (a public leak) is irreversible. Never add other suites to it.
- **Types**: `npm run check:types` = `tsc -p jsconfig.json`, JSDoc+checkJs, 0-error ratchet — catches nonexistent properties and LYING JSDoc (a block must be GLUED to its function; prose `@returns` is parsed as a tag).
- **Coupling**: `npm run check:coupling` = dependency-cruiser (purity rules) + jscpd (0% duplication tolerance beyond 1%).
- **`docfacts`**: `<!-- AUTO:name -->` blocks GENERATED from the constants (`node tools/language-doc.js --write`), gated on drift. Writing an ENUMERABLE fact in prose is FORBIDDEN — it is a copy, and a copy drifts; prose keeps only the judgement.
- **Concurrency**: `state/*.json` is protected by a cross-process lock (`lock.js`) — Claude Code launches independent tool calls IN PARALLEL, so shared state without a lock is a real race, not a theoretical one.
