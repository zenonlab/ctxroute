# differential-normalize.js — the reader that could make the differentials BLIND
⚠️ **SINGLE SOURCE of the 2 differentials** (`pretool-differential`, `mcp-differential`). Never a copy inside a suite: two normalizations diverge, and two nets that no longer filter the same thing no longer prove anything together. That is why the local `unseal()` of `pretool-differential` was DELETED on 2026-08-21 — a second reader of one envelope.
🛑 **IT REMOVES MATERIAL BEFORE COMPARISON** — legitimate (the `protect-files.js` oracle has been FROZEN since July and ignores everything born after: seal, ordinal, frames, chunks), but it demands its negative-check. An UNTESTED comparison filter can swallow a REAL regression, and both nets would stay GREEN on it.
🛑 **ANCHORED ON THE SOURCE TAG, NEVER A BLIND ERASURE**: removing every `[DOC x/y]` wherever it appears would swallow a doc whose BODY contains that text — the differentials would go one-eyed exactly where we thought we were strengthening them. Part ③ of the negative-check.
✅ **EQUALITY GIVEN BACK (2026-08-21) — `reassemble(frames)`, no more prefix.** A doc grown past one frame (~7,661 c) is CHUNKED while the frozen oracle returns it WHOLE. The first answer compared chunk 1 as a PREFIX and a divergence past it was INVISIBLE; the caller now DRIVES the frames the action declares and this module glues them back **by the protocol's own fields** (RFC 2046 `message/partial` + RFC 6455: `FRAME k/N`, `CHUNK j/m`, shared end marker), then the whole document is compared for EQUALITY. 🛑 NEVER "fix" a red by SHORTENING a doc — that degrades a deliverable to fit OUR plumbing.
🛑 **NEVER BY ARRIVAL ORDER**: no harness guarantees it (hooks run in parallel, aggregation unspecified). Frames are read by their NUMBER, the total and the end marker must agree across them, and a chunk missing, duplicated or out of order is a LOUD refusal.
🛑 **FAIL-CLOSED, ZERO FALLBACK**: `{ok:false, reason}` on an unparsable envelope · a frame from another emission · a lone-frame seal inside a multi-frame delivery · a continuation sitting mid-frame · a delivery that still DEFERS. The caller MUST stay RED — never fall back to a weaker comparison. Cell ② (a sabotage in the LAST chunk) is the one that proves the gap is closed and not merely renamed.
✅ **BOTH NETS NOW DRIVE THE FRAMES (2026-08-22) — the asymmetry lasted one day and it is the class this repo keeps paying for.** `mcp-differential` still spawned ONCE, passed no `--frame` and applied `withoutOrdinal` alone; measured harmless (its tmpdir fixtures peaked at 233 c against a 7,681 c frame, so nothing was ever chunked) and harmless BY LUCK OF SIZE — the same countdown the twin was on. 🛑 **TWO CALLERS OF ONE READER MUST NOT READ THE TRANSPORT TWO WAYS**, or the module is a single source in name only. ⚠️ Driving alone proves NOTHING: a net reassembling one frame every time is the old comparison renamed ⇒ each net owes a MULTI-FRAME cell whose frame count is ASSERTED, so a widened frame reddens it instead of silently making it single-frame again.
⚠️ **DECLARED GAP, BADGE ONLY, CHUNKED REGIME ONLY (`mcp-differential`, 2026-08-22)**: chunking makes `pretool-core` append `(chunk j/m)`, born 2026-08-06, after the frozen oracle — requiring strict badge equality there would forbid the fix that stopped N identical badges reading as a runaway framework. The old badge must stay an EXACT PREFIX and the supplement must be EXACTLY a position; **the CONTENT stays byte-strict in every regime**. 🛑 Never widen this to an `includes`, never drop the regime condition.
⚠️ **ONE DECLARED FALSE RED**: `fragment` cuts on LINE boundaries except on a line longer than a frame, which it chops mid-line; the two cuts are indistinguishable to a receiver, so such a doc reassembles one `\n` too long and stays RED. Loud and rare, preferred over a reader that guesses.
⚠️ TOTAL: a non-array, an empty array or a non-string frame is a REFUSAL, never a throw — a differential that crashes reads like an engine outage.
