# corpus-cache.js — the daemon stops re-reading what nothing changed
📐 **MEASURED 2026-08-20: a round trip is 41.49 ms of which the TRANSPORT is 0.17 ms.** The other 41 ms were the corpus re-read — the same cost the spawn lane paid, hidden inside node's startup. **The win was never in the pipe**, and anyone optimising the transport again is optimising 0.4 % of the problem.
🛑 **OFF BY DEFAULT, AND THAT IS WHAT KEEPS THE DIFFERENTIALS HONEST.** Only the daemon's `require.main` block calls `enableCache`; every spawned hook, the lint, `explain.js` and every test walk the disk exactly as before, so `pretool-differential` and `mcp-differential` run on the UNCHANGED path. A cache switched on globally would compare a cached engine against a frozen oracle and prove nothing.
🛑 **INVALIDATION IS A KERNEL EVENT, NEVER A TTL, A POLL, AN mtime OR A HASH.** The watch DROPS the entry; it never exits the process — that job belongs to `watchOwnCode`, and the two answer OPPOSITELY on purpose: a doc changing is normal, code changing is not.
🛑 **WATCH DIRECTORIES, NOT FILES.** Git renames over its target, so a file watch follows the dead inode and goes SILENTLY deaf — worse than no watch. The watched set is DERIVED from the walk itself (`dirsOut`), so a directory created tomorrow is covered: creating it is an event in its parent.
⚠️ **FAIL-OPEN, ALL-OR-NOTHING PER ROOT**: if any `watch()` throws, the watchers already armed are closed and that root is NOT cached — we hand back the freshly read corpus. **We never serve what we cannot be told about**, and we never crash the daemon for housekeeping.
⚠️ **CEILING 8 ROOTS, and it cannot grow with uptime, traffic or sessions** — the keys are `(directory, prefix)` pairs, never sessions. One entry is one snapshot of one root: ~4 MB for the biggest, a few MB in total. Past the ceiling we READ THROUGH rather than evict a neighbour: an LRU would let a fourth root thrash the three that matter on every request, which reads as "the cache does nothing" with nothing to see.
🛑 **EVERY HAND-OUT IS A FRESH ARRAY OF FRESH OBJECTS.** Without that, one consumer mutating an entry poisons every later request — a corruption visible only on the SECOND call, i.e. never in a test that makes one. A hand-out that is a STRING needs no copy — a string cannot be mutated — and copying megabytes would undo the point.
✅ **THE SKILL BODIES ARE RESIDENT TOO (2026-08-21) — one mechanism, TWO KINDS of entry, never a second cache.** `skillAdapter` reads through `corpus.readDoc`, which holds single FILES keyed by path in this same map, with the same `drop`, the same directory watch, the same fail-open and the same read-through. 🛑 Routing skills through `readCorpus` was REFUSED: it walks a ROOT, and the skills root is the harness's ~45 skills — every spawned hook would read ~5 MB to get the ONE body it matched, on the path production still runs.
⚠️ **A CEILING IS A POSITIVE NUMBER OR IT IS ABSENT** — `0` and any negative mean "the caller said nothing", so the DECLARED default applies; they never mean "hold nothing". A caller that wants the bound to bite passes 1 and fills it. 🛑 No `typeof` guard in front of that test: the only caller is `enableCache`, `undefined > 0` is already false, and a guard nothing can reach is dead code that freezes itself.
⚠️ **`cachedWatchers()` IS THE OBSERVABLE OF A BOUNDED OS RESOURCE** (inotify watches, file descriptors) on a process that runs for weeks, and the only way to prove from outside that ONE watch was armed per walked directory — one too many is a leak, one too few is a directory nobody can be told about, i.e. a stale corpus served in silence. ⚠️ It TRAVERSES the map: observability only, never the hot path (`size`/`fileCount` are exact integers for that reason).
⚠️ **ONLY THE FILE KIND NAMES ITSELF** — a root entry carries no `kind`, because the one reader is `=== 'file'` and any other value behaved identically: dead data that reads like a decision. A third kind turns that equality into a switch and every kind names itself again.
⚠️ **FILE CEILING: 16 files AND 4,194,304 characters**, both, because one alone is refutable — the count is defeated by a single pathological file, the characters by thousands of tiny ones. Arithmetic: ~45 skills × 90–120 KB ≈ 5.4 MB if everything were held; 16 × 120 KB ≈ 1.9 MB of characters (~3.8 MB of RAM, a V8 string costing up to 2 bytes per character). Past either bound: READ THROUGH, never evict.
