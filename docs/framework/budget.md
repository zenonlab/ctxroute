# budget.js — DELIVER EVERYTHING, never judge size (NO undeliverability left)
⚠️ **THREE PATHS.** It fits in the frame ⇒ emit as-is (zero envelope, zero loop). It overflows ⇒ **split into chunks** spread over N frames. It overflows AGAIN ⇒ **QUEUE** (`emission-core.js`, prefix `remainder-`) for the next action. ⚠️ The queue and the splitting no longer live in `pretool-core.js` (moved 2026-08-05, ⑯): this PURE module is called by the EMISSION LAYER, which every emitter goes through — `orderSegments`/`baseId` (RFC 6455 order + per-document dedup) are here, the I/O is over there. Undeliverability is therefore impossible **without reservation** since 2026-08-05: any size gets through, over several actions if needed. `--frames N` is no longer a ceiling, only a **THROUGHPUT**. NEVER reintroduce a size ceiling nor a "too big" — that would make a doc's author carry a TRANSPORT defect.
⚠️ **PROTOCOL = RFC 2046 `message/partial` + RFC 6455** (not a homemade invention): each chunk carries the 3 mandatory fields — **id** (the shared marker `###END:xxxx###`), **number starting at 1**, **total** — and each frame carries `FRAME k/N`. Cut on **line boundaries**, strict order, never interleaved. Removing a single one removes a reassembly guarantee. Detail, sources and measurements → `budget-frames-reference.md`.
⚠️ **NEVER write a harness threshold here** — the number comes from the SHELL (`options.budget`); conservative floor 8,000. 🔴 **DOCUMENTED FACT (official doc `code.claude.com/docs/en/hooks`, read 2026-08-05) — two of our claims were FALSE**: the Claude Code limit IS documented (**10,000 characters** — RE-VERIFIED UNCHANGED 2026-08-08, no limit removal in the changelog, not "internal undocumented") AND overflow is **NOT a silent truncation**: *"saved to a file and replaced with a preview and file path"*. So the harness has a NET — but it cannot catch us as long as we THROW AWAY the surplus before emitting it (cf. leftover queue + REFACTOR-PLAN ⑭). 🛑 Do NOT peg a constant to 10,000 anyway: it can change without notice — we consume this fact only to stop throwing away. Codex: `additionalContextLimit` **is DECLARED in our own wiring** (per hook, next to `command`) — nothing to read, we write it as `0` = full delivery ⇒ **no fragmentation needed on the Codex side** (fixed 2026-08-04: "we READ it" was false, it is not an upstream config). Without that line, default **2500 TOKENS** then disk spill + preview, SILENTLY. Required by `doctor.js --codex-hooks`. Rule: **negotiate when an authority exists, floor otherwise.**
🛑 **CONTRACT, AND IT IS THE KEY TO EVERYTHING: the framework EMITS everything it decided to inject — its promise STOPS AT EMISSION.** What the harness does with the surplus is NOT our promise and must NEVER become one: Anthropic published NO interface for building a system on top of hooks, so nothing binds them to warn — a behavior not designed as an API disappears WITHOUT deprecation. **Test to apply to EVERY line written here: "if the harness threw away the surplus tomorrow, would this code change?" — the answer MUST be NO.** Permanent bans: coding a harness constant (10000…) into the engine · reading/probing the spill file · making a decision depend on its existence · promising in docs that the surplus is recoverable. Emitting everything wins in BOTH worlds.
⚠️ **`Infinity` = "THIS HARNESS BOUNDS NOTHING", a LEGITIMATE value (2026-08-05)** — not an accident to filter out. Measured in the Codex 0.146.0 binary: `additionalContextLimit = 0` literally means *"disables spilling"*. The original `Number.isFinite` rejected infinity and fell back to the FLOOR: a 76,000-char skill went out in **11 actions instead of 1**, SILENTLY, with 995 green tests, 100 % mutation, doctor 27/27 and a live canary. **A GREEN THAT LIES — not an outage, a degradation.** Infinite budget ⇒ one frame, no seal and no chunking (nothing can be truncated, so nothing to signal).
⚠️ **Unit = the CHARACTER** (what the harness counts), never the token.
⚠️ **CONSERVATION = the central invariant**: every doc that enters comes out delivered (whole or as `id#j` chunks) or signalled. **Never evaporated** — REAL bug of 2026-08-03 where a tiny frame made content vanish. Sealed by property-based + negative-check via sabotage.
⚠️ **A LEFTOVER IS A DELAY, NEVER A LOSS.** The capacity of ONE call is FINITE — the harness starts exactly the frames declared cold, we cannot create an extra one during the call. **Measured 2026-08-07: 1 frame = 7,661 c · 12 frames = 91,932 c · worst real load 65,265 c (71 %), of which 53,830 c for the skill alone.** The surplus is never thrown away: it waits in the queue and leaves on the next action — **exactly the TCP sender**, which buffers when the window is full. 🔴 **BUT a leftover is NOT harmless: the agent ACTS before having received everything.** ⇒ **the overflow message MUST say to increase `frames`** (explicit maintainer decision, 2026-08-07 — this line FORBADE it, that was a framing error: deferral was treated as a normal phenomenon while it degrades the agent's decision). This is not toil: it is a CAPACITY setting only a human can arbitrate, since increasing it costs ~330 ms of process per frame and per tool call. 🔴 **AND THAT PRICE BELONGS TO THE `command` LANE, NOT TO `frames` — measured 2026-08-20.** Claude Code 2.1.237 really implements `type:"http"` (verified in the binary, not only in the doc): the frame then costs one local POST instead of a node startup, so on that harness `frames` stops being an arbitration between capacity and cost. 🛑 The **10,000 c cap is per OUTPUT, not per process** ⇒ N declarations remain REQUIRED either way. Codex 0.146.0 has no such handler (*"Only `type:"command"` handlers run today"*) and stays on this lane. Detail and the remaining unknown → `http-lane.md`.
⚠️ **THREE INTERLOCKED GUARDRAILS, otherwise the queue LOOPS (defects MEASURED 2026-08-05)**: ① the announcement counts **DOCUMENTS** (dedup by label) and cites **5 max** — otherwise 56 chunks of a single doc filled the frame; ② **progress guarantee**: if nothing fits, force ONE chunk and SACRIFICE the announcement (*delivering comes before describing*); ③ `fragment` **drops the chunk header** when capacity cannot carry it — otherwise it returned a chunk bigger than its own bound (419 c measured for a budget of 340). Removing one = infinite loop or over-budget frame.
⚠️ **`n === 1` ALSO CHUNKS** (Codex's regime): the "n=1 ⇒ return `planifier()`" short-circuit was a HOLE — `planifier` does not chunk, so an over-heavy doc NEVER arrived. The guaranteed parity is that of the case **THAT FITS**, never of the one that overflows. A lone frame carries the SIMPLE header, never "FRAME 1/1" (an absurd reassembly instruction).
⚠️ **It is the ENVELOPE that yields, never the content.** Budget too small to carry the seal (`frameCapacity` ≤ 0) ⇒ we **UNSEAL and deliver** (marker returned empty — never announce a seal absent from the text). REAL bug of 2026-08-03: without this path, ZERO docs went out and the message blamed `--frames N`. Delivering comes before sealing. No content is ever too small NOR too big: 2 characters go out as-is (path 1).
⚠️ **The seal is what makes us update-resistant.** The header announces the end marker; marker missing on read ⇒ the harness truncated, and the agent KNOWS it. The mechanism assumes NO threshold value: it holds at 10,000, 4,000 or 400,000. That is what makes a lowered limit LOUD instead of silent.
⚠️ **PARITY**: under 50 % of budget, HISTORICAL byte-identical output (no seal, no header) — that is what keeps switchovers safe.
⚠️ **Property generators: budget RELATIVE to sizes.** Two sabotages passed GREEN on 2026-07-31 (fast-check bias toward small values). The ⑦ COVERAGE meta-test seals this — NEVER remove it as a duplicate.
⚠️ **A CHUNK'S ID CARRIES `#j/m`, NOT `#j` (2026-08-06)** — the TOTAL existed nowhere outside the header text, so the badge could not say "chunk 3/7" and displayed N IDENTICAL lines: read as the framework running wild while delivery was normal. **A correct but ILLEGIBLE transport gets mistaken for an outage.** `baseId` reads the FIRST `#` (the base), `partMorceau` the LAST (a re-chunked chunk carries `doc#3/7#2/4`) — never confuse the two. `suffixeMorceaux` is DESCRIPTION: computed after the split, it does NOT enter the budget and can evict NOTHING.
