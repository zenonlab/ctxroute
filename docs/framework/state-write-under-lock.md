# state-write-under-lock-gate — the queue invariant is no longer carried by prose

- 🔑 **WORK ITEM 58 IS ANSWERED: the cross-process lock MUST exist.** The critical section is a **leader election + memoized plan** across N parallel frame processes (one decides and writes, the others read the plan back), never a per-doc counter — so decomposing state per doc would NOT remove it. It already uses the OS primitive (atomic `mkdir`): nothing is reimplemented.
- 🛑 **SCOPE = WRITES ONLY.** Reading never needed the lock, and putting `{}` back on the lockless path was a real production bug (orphan chunk). Do not widen this gate to reads.
- ⚠️ **DERIVED from the SHAPE of a write** (`ast-grep`, never regex), so a writer added tomorrow is covered the day it is written. The rule ALSO matches `.emit(` — that half is what makes the `emission-core.js` exemption TRUE rather than trusted — and, since 2026-08-23, `.purge(` / `.purgeByPrefix(`: **a DESTRUCTIVE write is a write**, and the PreCompact sweep was the last durable writer with no lock (TLC `StatePurgeWindow`).
- ⚠️ **An ALIAS that hides a write is FLAGGED, and that is intended** (it bit on `legacy-mcp-inject.js`): once a write sits behind an indirection, its safety can no longer be read at the call site. Justify it or unwrap it.
- 🛑 **EXEMPTION = the caller holds the lock, or a RELIC — with the reason.** The INVERSE part turns red as soon as an exemption stops being needed. Never list a LIVE unlocked writer.
- 🔴 **AN EXEMPTION WHOSE TRUTH DEPENDS ON A FACT ELSEWHERE GOES STALE WITH NOTHING GOING RED (2026-08-23).** The daemon was exempted as *"nothing to serialise against — one process, one thread"*, WITH its own expiry clause; the clause fired on 2026-08-22 when the daemon became a write-through cache onto the files a spawned peer locks, and only a human reading the routes noticed. **MEASURED: 209 lost read-modify-writes out of 800** on one `remainder-` key (control, both writers locked: 0-1).
- 🛑 **SO AN EXEMPTION NOW NAMES THE MACHINE THAT RE-READS ITS CONDITION — `{ kind, reason }`, kind from a CLOSED list, and that distinction is MECHANICAL, not documentary.** `guarded-by-scan` = the reason is re-established BY THIS SCAN ("my callers are matched here, so an unlocked one turns this gate red") — safe, and cell ① is what keeps it safe: the writer surface is DERIVED from the WHOLE repository and a state write appearing outside the judged roots is RED, because it would break that claim for every such exemption at once. `unwired-relic` = the reason asserts a fact about ANOTHER file, so cell ② re-reads that file twice over: absent from `wiring.json`'s consumers AND imported by nothing. **A new kind owes a new cell.**
- ⚠️ **ANTI-VACUITY EVERYWHERE, because "I could not measure" is never "all is well"**: a bare-string exemption, an unknown kind, a missing file, an empty table, a repository-wide scan that reaches one directory or finds under ten writes, an import probe under ten `require()` calls — all RED. Seen red on three sabotages: a writer planted outside `src`/`tools`, the relic declared in `wiring.json`, and a live `require()` of the relic.
- 🛑 **THE STATIC RULE PROVES A LOCK IS HELD, NEVER THAT IT IS THE RIGHT ONE.** `withLock(otherDir, …)` passes it and protects nothing. The ADDRESS has one owner, `store-resolve.docLockDir` / `turnLockDir`, and a behavioural cell (`daemon-is-a-cache.test.js` ⑤) checks it is held AT the instant of the write.
- ⚠️ `ast-grep scan` **exits non-zero on any match**: that is a FINDING, not a tool failure — read stdout, never let it throw, or every defect would be reported as "tool broken".
