# paths.js — single source of paths

⚠️ EVERY runtime path (config/docs/state) is declared HERE, once. NEVER redo an ad-hoc `path.join(__dirname,'state')` in a hook: `stateDir` was duplicated identically in inject.js AND reset.js — two copies of one truth that diverge silently (the reset would target another folder, with no visible error).
LAZY resolution mandatory (`paths.stateDir()` at call time, never frozen in a const at load) — otherwise the env vars set by the parent at spawn are ignored.
⚠️ **THREE DIRECTORIES AND ONE LISTENING ADDRESS ARE DECLARABLE, AND THE CONFIG'S OWN ADDRESS IS A LAUNCH ARGUMENT (2026-08-24, the endpoint 2026-08-25)** — `stateDir` · `docsDir` · `sessionDocsDir` follow ONE precedence: `CTXROUTE_*_DIR` > the config key > the code-derived directory; `http` follows the SAME shape (`paths.httpEndpoint()`: `CTXROUTE_HTTP_PORT` > the config key > 127.0.0.1:8787) with TWO declared differences — that variable is NOT test-reserved (`service/ctxroute-http.service` declares it and `service/install-windows.ps1` reads it back), and it moves the PORT alone because no supervisor ever names a host to us and an INHERITED variable able to move the bind off the loopback would expose the fleet's private knowledge on an endpoint that has no authentication. 🛑 It is a SINGLE resolution point returning the address WHOLE, because that address has TWO consumers, the daemon that BINDS it and `tools/wiring-generate.js` that writes it into the URL the harness POSTs to; each held its own copy of BOTH halves until then, agreeing by luck with nothing comparing them. 🛑 And it is ONE grouped key rather than a `httpHost` beside a `httpPort`: an address is ONE fact, so it is read entire or it is read twice. The CONFIG itself cannot declare its own location, so it is `--ctxroute-config <ABSOLUTE path>` (`CTXROUTE_CONFIG_PATH` still FIRST, and read BEFORE `argv` is even parsed). **Nothing declared = the historical addresses, byte for byte**: zero default change is the acceptance criterion, not a preference. 🔑 They exist because the address of the DATA was DERIVED from the address of the CODE, so a second copy of the code was a second state AND a second corpus — a SPLIT BRAIN, the only failure this repository refuses outright being the SILENT one; freezing the code (the cure for the daemon's stale-code exit) would otherwise freeze the maintainer's docs with it and their edits would stop reaching production. 🛑 **The env vars MUST keep winning**: reserved for tests and doctor.js, they are how every suite isolates itself in a tmpdir — a config beating them sends those suites writing into the REAL state. 🛑 **NEVER an env var for the config address**: env vars are INHERITED, and one leak makes a spawned hook read a FOREIGN config; the flag is NAMESPACED because a bare `--config` already belongs to vitest and dependency-cruiser in this package's own scripts, and `paths.js` is loaded INSIDE those processes. 🛑 A RELATIVE (or empty, or duplicated, or otherwise invalid) declaration is a NAMED REFUSAL saying the key — or the flag — AND the value, NEVER a quiet fallback: that fallback IS the defect, since the operator would believe their data lives where they wrote it. ⚠️ The DECISIONS live in `src/declared-paths-pure.js` (pure, mutated, `path.isAbsolute` and `argv` INJECTED — never a regex of ours, never a global read); `paths.js` alone reads the config and `process.argv`, which is what makes EVERY shell honour the argument by construction, and an UNREADABLE config is an ABSENT config (fail-open, like every other reader) while a READABLE one that declares nonsense is refused.
⚠️ **AND THE CONFIG IS ALSO LOOKED FOR WHERE THE OPERATING SYSTEM PUTS ONE (stage ③, 2026-08-24)** — full precedence: `CTXROUTE_CONFIG_PATH` > the `--ctxroute-config` argument > **the OS-conventional per-user file IF IT EXISTS** > `ROOT/ctxroute-config.json`. 🛑 **EXISTENCE-CONDITIONAL ON PURPOSE**: with no user-level file every resolution is byte-identical to before, which is what makes this invisible to every install already running — zero default change is the acceptance criterion. 🔑 TWO reasons, one cure: a FROZEN copy of the code (the cure for the daemon exiting on its own source change) had no way to find the LIVE config, and this repository being PUBLIC, an adopter's config had to live INSIDE the clone, where a `git pull` or a re-clone DESTROYS it. 📚 **DOC-FIRST, sources dated in the module header, never invented**: XDG Base Directory Specification 0.8 (08 May 2021) — `$XDG_CONFIG_HOME`, defaulting to `$HOME/.config` when "not set or empty", all such paths "must be absolute" · Microsoft KNOWNFOLDERID (page 2020-07-27, revised 2023-08-30) — `FOLDERID_RoamingAppData`, PERUSER, `%APPDATA%` = `%USERPROFILE%\AppData\Roaming` · Apple File System Basics (2018-04-09) — `~/Library/Application Support`, and `~/Library/Preferences` EXCLUDED by that same page ("You should not create files in this directory yourself"). Under that root: `ctxroute/ctxroute-config.json`. ⚠️ The DECISION is `declared-paths-pure.conventionalConfigParts` — platform, environment and home all INJECTED (which is what proves the three platforms from ONE host) and it returns SEGMENTS, never a path, because the separator is `path`'s knowledge; the EXISTENCE check is I/O and therefore lives in `paths.js`, next to the `path.join`. 🛑 A RELATIVE `XDG_CONFIG_HOME`/`%APPDATA%`, or an unusable home, is a NAMED REFUSAL — a DECLARED divergence from the XDG spec, which says to IGNORE such a value: that wording is written for a desktop application, whereas this address decides which RULE SET a whole fleet obeys, so substituting a directory the environment never named is the "two callers, two configs" defect. An UNKNOWN platform takes the XDG lane (the spec is not Linux-only), and an unset or EMPTY variable is not malformed — it is the spec's own wording for "take the default".
Every env var here (`CTXROUTE_CONFIG_PATH`/`DOCS_DIR`/`STATE_DIR`/`FILEDOCS_DIR`/`SESSIONDOCS_DIR`/`SKILLS_DIR`/`FLEET_HOOKS_DIR`/`TRANSCRIPTS_DIR`/`SECRETS_DIR`, plus `CTXROUTE_LEAK_LIST`) is RESERVED for tests and doctor.js — never a user setting (that is `ctxroute-config.json`).
⚠️ THE FLEET ROOT = `FLEET_SEGMENTS` (2026-08-21), ONE definition with TWO projections that must NEVER be collapsed: `fleetHooksDir()` = ABSOLUTE, anchored at the home, overridable — the address a PROCESS uses to REACH the disk (`fileDocsDir()` hangs beneath it, `skillsDir()` beside it); `fleetHooksLabel()` = RELATIVE, POSIX, home-free, NOT overridable — the address PUBLISHED to a reader in the `[source: …]` tag.
🛑 NEVER emit `fleetHooksDir()` into a tag, a message or a doc: it returns the maintainer's real home (a tmpdir under the test override), and this repository is PUBLIC and treats itself as already public — that is a LEAK, and a test override would rewrite a published contract. The tag is a CONTRACT (an agent reads that exact path to go UPDATE the doc), so a stale prefix breaks the self-repairing loop with nothing going red. Two projections of one truth is the fix; one function is a leak.
⚠️ THE HARNESS ROOTS ARE A REGISTRY, `harnessRoots()` — FOUR since 2026-08-22: `fleetHooksDir` · `transcriptsDir` (`~/.claude/projects`, the harness TRANSCRIPT corpus, read in bulk by `tools/scope-reach.js`) · `skillsDir` · `secretsDir` (`~/.claude/secrets`, the private anti-leak list, reached through `src/leak-list.js`). Declare a root there ONLY if this module owns its accessor. Frozen at every level (a mutable registry moves a root for everyone, at runtime, including for its own judge).
🔴 THE `secrets` ROOT WAS THE LAST DECLARED OMISSION, and its note is GONE because it stopped being true (2026-08-22). `src/leak-list.js` rebuilt `~/.claude/secrets` from `os.homedir()`, and a note beside the registry called that omission DELIBERATE — "declaring it would accuse a file this module owns no accessor for". Honest, dated, and still an UNPOLICED harness root: that is the shape every permanent exemption takes. 🛑 "The gate would redden the truth" always means the truth is in the WRONG PLACE — move it (give `paths.js` the accessor), never leave the root out. Highest stake of the four: it addresses a SECRETS directory, and a silent move makes the anti-leak gate read an EMPTY list, i.e. run in GENERIC mode believing itself armed, i.e. stop protecting the names it exists for while going GREEN.

Whoever must SAY where the list goes says it with `privateListLabel()`.
