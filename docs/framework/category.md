# `category` — WHO is acting: a FILTER, never a trigger (22/09/2026, identity 07/10/2026)

⚠️ `category` NARROWS an injection another trigger already selected (`match`/`tool`/`mcp`/`rules`, or the session folder) — it belongs to the `enforce`/`filterMode` family, NEVER to `match`'s. Absent on a doc/skill/tool-entry = universal, unchanged behaviour (parity — this is what every pre-existing doc still does).
🔑 **TWO DIMENSIONS, NEVER MIXED (operator, 2026-10-07)**: `match`/`scope`/`exclude` say WHAT the gesture contains and never see who performs it (observable-reach keeps `agent_id` blind to them, with its reason); `category` says WHO is acting. The identity therefore reaches the language through `category` ONLY — a new word for it would be a synonym.
⚠️ **THE MEANING LIVES IN ONE PURE MODULE, `src/category-pure.js`**, read by the validator (`frontmatter` registry), the gate (`categoryExcluded`) and both shells. Never restate it elsewhere.
⚠️ **FORMS** (same as `scope`): flat `["a","b"]` = ONE group, a OR b (the 22/09 meaning, untouched) · grouped `[["a"],["b"]]` = AND of groups · mixed = REFUSED. `parse()` reads `[[` as JSON for `category` like for `scope` (the note-55 trap: cut on its commas a grouped value becomes flat literals, refused by nothing).
🛑 **A `-name` SUBTRACTS, IT NEVER JOINS THE OR.** A group holds ⇔ (no positive, or one positive carried) AND every negative is MEASURED and NOT carried. `["role:subagent", "-type:Explore"]` = sub-agents except Explore. Read as an OR it meant "sub-agent OR not Explore" and let the MAIN agent in — caught by a senior review before a line was written. Same shape as `exclude` (∀¬).
🛑 **FAIL-CLOSED, ONE RULE**: an unmet positive excludes (a session that declared nothing still misses a doc requiring `ops`, as on 22/09); a negative on a fact the harness did not deliver excludes too — otherwise `-type:Explore` would leak to an Explore whose type nobody saw. A list of negatives alone means "everyone except".
🔑 **DERIVED IDENTITY (2026-10-07)** — computed PER GESTURE by `contextFacts`, never stored, never inherited, added to the declared names: `role:subagent` when the payload carries the harness's id field · `role:main` when it carries none AND the harness is known to send one for every sub-agent gesture (`sendsAgentId`), otherwise NO role (tri-state: an absence proves nothing on an unknown harness) · `type:<agent_type>` from the type field. Field names come from `harness-profile.IDENTITY.<harness>`, never written in the engine; the shell passes its profile (`identity` option, or `--harness` for the shared session shell).
📐 **MEASURED 2026-10-07 on Claude Code** (real `claude -p` capture with a recording hook): every PreToolUse of a sub-agent carries `agent_id` + `agent_type`, the main agent's carries neither; SubagentStart carries both but NOT the parent; PostToolUse(Agent) names the child only once it finished. Codex: `agent_id` per its contract, `agent_type` on a PreToolUse NOT measured ⇒ `type` unmeasured there, fail-closed.
🛑 **NO `depth:`** — no harness names a sub-agent's parent, so a depth is never a fact; `depth:`, an unknown `role:` and an empty `type:` are refused by the validator and offer nothing to the cascade (a doc restricted to a fact that never exists would be muted forever). Claude Code DOES nest sub-agents (3 levels by default, doc `sub-agents.md`) — the fleet's no-agent-cascade hook is what keeps it at one level here.
🛑 **RESERVED NAMESPACES**: `role:`, `type:`, `depth:` and a leading `-` belong to the language; `contextFacts` DROPS a declared category spelled that way (a policy must never forge an identity).
⚠️ An identity restriction leaves the gesture SILENTLY (a main-only doc meeting a sub-agent is the expected shape of a fleet, never news); only a restriction on DECLARED names feeds `categoryOut` and its badge (`namesIdentity`).
⚠️ 2-stage cascade only, like `enforce`: entry > `defaults.{source}` — **NO global stage** (a global restriction would silence the fleet's very first gesture of every session). The session corpus has its own stage, `defaults.session`, which carries `category` ONLY (`atStart` in the setting registry).
🛑 **THE DECLARED CATEGORIES ARE NOT A HARNESS FIELD.** A role a policy attributes is a fact `ctxroute` reads from its own store (`src/category-store-pure.js`, session-scoped, keyed by `lib.scopeId`) — only the IDENTITY above is read from the payload. `gate.decide`'s 8th argument is the caller's `contextFacts(...)`; a bare list is the older contract and now carries nothing (fail-closed).
🛑 **PHASE 1 IS READ-ONLY, ON PURPOSE.** This repo ships the neutral primitive but NO command that SETS a session's category — that mechanism (a human command, an agent self-tag with a mandatory reason, a launcher flag) is an OPINION about HOW a role gets attributed, and lives in `ctxroute-policies`, like the `cd` wall's authorize/scope commands. Deriving the identity is NOT an opinion: it reads a field, it guesses nothing.
✅ **WIRED (2026-09-22)**: `pretool-core.js` loads `category-<scopeId>.json` through `session-store.js` on both `gate.decide` call sites (locked path and lock-less fallback) and hands `contextFacts(declared, payload, identity)` as the 8th argument. One object per scope (`{categories: [...]}`); purged at PreCompact (`ctxroute-reset.js`, prefix `category-`), `durable` in `state-eviction-pure.js`, locked under `docLockDir`. Proven by a REAL spawn of the production hook (`test/category-wiring.test.js`).
✅ **PARENT → SUB-AGENT INHERITANCE OF THE DECLARED NAMES, ONE LEVEL, MEASURED (2026-09-22)**: a sub-agent with no category of its own reads the bare-session state (`lib.scopeId(session_id, undefined)`); its OWN declaration always wins (never merged). The derived identity is never inherited — a sub-agent is never `role:main`. 🛑 HONEST LIMIT: no harness names the parent of a NESTED sub-agent, so a chain deeper than master→sub-agent cannot be resolved this way.
⚠️ Judges: `cadence-spec.js` models the WHO semantics from the intention (①bis 44,965 exclusion cases, ⑥ 391 decision cases, 0 divergence, a subtracting-`-` sabotage turns 25,670 red); `observable-reach-gate` proves identity is reached by `category` positively AND negatively; mutation 100 % on `category-pure.js`.
