# `category` — a FILTER, never a trigger (Phase 1, 22/09/2026)

⚠️ `category` NARROWS an injection another trigger already selected (`match`/`tool`/`mcp`/`rules`) — it belongs to the `enforce`/`filterMode` family, NEVER to `match`'s. Absent on a doc/skill/tool-entry = universal, unchanged behaviour (parity — this is what every pre-existing doc still does).
⚠️ A doc that DOES declare `category: [...]` only injects if it recoups the SESSION's own declared categories (OR semantics, like `match`). No session category declared ⇒ EVERY categorized doc is excluded — fail-CLOSED on the restriction, the inverse of `enforce`'s own fail-open.
⚠️ 2-stage cascade only, like `enforce`: entry > `defaults.{source}` — **NO global stage** (a global restriction would silence the fleet's very first gesture of every session).
🛑 **THE SESSION'S OWN CATEGORIES ARE NOT A HARNESS FIELD.** No harness exposes "this agent's role" — it is a fact `ctxroute` itself declares and reads (`src/category-store-pure.js`, session-scoped, keyed by `lib.scopeId`). `gate.decide`'s 8th argument (`sessionCategories`) is supplied by the CALLER; the gate never invents it.
🛑 **PHASE 1 IS READ-ONLY, ON PURPOSE.** This repo ships the neutral primitive (the filter + `pretool-core.js` actually READING it on every real gesture, proven by real spawn) but NO command that SETS a session's category — that mechanism (a human command, an agent self-tag with a mandatory reason, a launcher flag) is an OPINION about HOW a role gets attributed, and lives in the separate `ctxroute-policies` layer, exactly like the `cd` wall's own authorize/scope commands.
✅ **WIRED LIVE (2026-09-22)**: `pretool-core.js` loads `category-<scopeId>.json` through the SAME `session-store.js` mechanism as `doc-seen-`/`turn-count-`, on both `gate.decide` call sites (the locked path and the lock-less fallback), and passes it as the 8th argument. State shape = ONE object PER SCOPE (`{categories: [...]}`), never a multi-session map — `src/category-store-pure.js` only shapes what a caller already loaded/will save. Purged at PreCompact like every other per-scope state here (`ctxroute-reset.js`, prefix `category-`), classified `durable` in `state-eviction-pure.js`, locked under `docLockDir` (`store-resolve.js`'s `DOC_KEYS`) — a deliberate choice, not a default: a declared role is treated as ORDINARY session memory, not identity, so it resets on compaction exactly like `doc-seen-` does. Proven end to end by a REAL spawn of the production hook (`test/category-wiring.test.js`): a categorized skill matching normally on a path is excluded for a session under the wrong category, included under the matching one, excluded when no category was declared at all, and an uncategorized doc stays unaffected either way (parity).
✅ **PARENT → SUB-AGENT INHERITANCE, ONE LEVEL, MEASURED (2026-09-22).** `lib.scopeId(session_id, undefined)` — the bare, sanitized `session_id` — is exactly where the MASTER's own category lives, and `session_id` is the ONE field both measured harness contracts (Claude Code, Codex ≥ 0.146.0) already document as SHARED between a master and every sub-agent it spawns. So a sub-agent with no category of its own (`agent_id` present, its own scoped state empty) falls back to reading the bare-session state — zero new harness capability needed, proven by real spawn. The sub-agent's OWN category, when declared, always wins (never merged). 🛑 **HONEST LIMIT**: neither harness's payload names WHICH `agent_id` is the immediate parent of a NESTED sub-agent — only "this session" and "this agent_id" are exposed — so a chain deeper than master→sub-agent cannot be resolved this way. Not invented: this repo's own measured architecture doctrine already states sub-agents are not recursive today (a manager dispatches N agents on N disjoint scopes), so the unresolvable case does not arise on the fleet this ships to. Re-measure before assuming otherwise if that ever changes.
⚠️ Founding case: replacing the `cd`-authorization wall's actual protection (a foreign project's whole skill injecting when an agent wanders in) — tag every project skill with its OWN category, declare each session's category at start; the wall keeps blocking the `cd` action itself (a DIFFERENT problem: not "what gets shown" but "what's allowed").
