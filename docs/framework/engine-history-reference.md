# Engine history — dated incidents, measurements, closed defects

ON-DEMAND page (never re-injected). The short invariants live in the skill; here is the full WHY for whoever ports the mechanism, doubts a claim, or wants the story behind a rule.

## Publishing discipline — the incident that founded it (2026-08-31)
The rule ("nothing reaches the public remote while `npm run test:all` is red") was born of a fault committed here in full knowledge: the CI was READ before publishing (`test`, `mutation`, `service-units` all failing) and the version shipped anyway, on the reasoning "it was already red before my commits, so I am not making it worse" — a REASONING, not a measurement, the exact shape of decision this repository refuses everywhere else.
Prose alone could not hold it: `.githooks/` only carries `pre-commit` (anti-leak) and `commit-msg`; the documented publishing form (`git commit-tree` then `git push`) bypasses both, and there is no `pre-push` (a local hook is one `--no-verify` away anyway). The rule now lives server-side: GitHub branch protection with required status checks (`test` + `coupling` only — never `mutation`/`service-units`, a lock that makes every publication unbearable gets switched off). Armed only once the CI is green.
One exception, written because the rule forbade its own repair (2026-09-01): a commit whose ONLY content is the fix for the current red may ship while it stands — otherwise the rule refuses the progress it demands, since the CI is the only witness and it runs on the public repository alone. Disappears the day a private CI-before-publish exists.

## Cross-OS verdicts — the reflex that failed once (2026-09-19)
A macOS shim was written, reviewed, and filed as "provable only by the CI, hence out of reach of this session" while the `workflow_dispatch` trigger had been sitting in the very same workflows since 2026-08-21, reasoning written beside it. Nothing was missing but the thought — this project's own thesis (deliver knowledge at the moment of the act) turned against it, because that day nobody had touched the doc scoped to `service/`. The only real blocker ever measured here was `gh run list` answering "no git remotes found" (no remote ⇒ nowhere to push, no Actions tab) — say that, with the measurement, never "impossible" and never "later". A macOS runner bills ×10 the Actions minutes (Windows ×2, Linux ×1), hence the strict `paths:` — a dispatch is a gesture you choose, never a habit, but choosing not to is a decision you write down.

## Live production — dated incidents behind the rules
- **Frames sizing** (2026-08-12/22): at 16 frames the skill alone took 121,809 of 122,944c, leaving 0.9% for every other doc — `capacity-alarm` went red on the real fleet corpus. Raised to 32 the same evening (245,888c capacity). Falling back to `--frames 1` "to guarantee ordering" was tried and cancelled 06-07/08/2026: capacity would drop to ~7,661c, forcing the agent to act on partial knowledge for N-1 actions. Ordering is guaranteed by no harness (official doc: hooks run in parallel, aggregation unspecified) — demanding it bets on the undocumented.
- **English-only rule, three real violations in four days** (16/08/2026 onward), always by an agent that had JUST read the rule — including a French paragraph surviving in the mirror a fork receives. This is why the rule is now THREE machines and not prose: `english-only-gate` (prose, scoped to `docs/framework/`), `commit-msg` (the whole message), `foreign-identifier-gate` (identifiers — 888 foreign occurrences / 508 names / 138 files measured, already shipped in the published repo, renamed to 0). Both detectors chosen by measurement against the market leader: `franc` gave 97 false positives here, `eld` gave 0 and caught 2/2 real violations; `cspell` with an English dictionary inverts the burden of proof (anything not KNOWN-English reddens, including legitimate loanwords). A foreign identifier is renamed, never added to an allowlist — the one invisible way to disarm the gate. Declared blind spot: English keeps French loanwords (`chemin`, `parc`, `nom`, `sortie`, `garde` all pass) — never use one as a witness string.
- **Frontmatter JSON-first parsing** (15/08/2026, ㊵㊵/55): `scope`/`exclude` starting with `[[` are parsed as JSON in `parse()` — before this fix `parseList` mangled the grouped form into valid flat literals, so a rule was born dead in silence; the fleet's first doc to write the grouped form (`live-production.md` itself) was the stillborn one.

## Where things are — the incidents behind each fact (2026-08-22 onward)
- **`pretool-core` hands an adapter BASES, never segments.** A fix shipped DEAD on this fact with a green suite (2026-09-13): it mapped `baseId` over `plan.emitted` before calling `message()`, so `injected` carried `doc.md` with the `#j/m` already gone — a correction asking `chunkPart(injected[0])` answered `null` for every real delivery while six cells passed, because they fabricated ids carrying `#`, exercising a caller that does not exist. The operator found it by reading a badge. Closed by `rules/no-fabricated-segment-id.yml` + a dedicated gate, zero tolerance, no budget file (the class has no legitimate occurrence).
- **Production runs a frozen copy** (`Desktop/ctxroute-release`) since 2026-08-24. `watchOwnCode` exits the daemon on its own source change; running from the working directory used to cost the whole fleet its injection window on every edit — 169 deaths in one day. "The frozen copy makes the cause disappear" was FALSE, measured the same day: nothing had written to the frozen copy and the daemon still killed itself 258 times, because libuv's ReadDirectoryChangesW watches `FILE_NOTIFY_CHANGE_LAST_ACCESS` and NTFS may defer that write by up to an hour — merely READING a file was enough. The real cure made freshness an OBSERVATION at the point of use, proven by editing a working-repo file and watching the daemon stay alive with HTTP 200. Extracting into the existing directory (never build-beside-and-rename) was learned the hard way: Windows holds the running daemon's directory, a rename fails `Permission denied`, and killing the daemon to free it re-triggers the exit-90 restart which re-locks it.
- **Every address is declared, four instances closed in one day** (2026-08-25), each found by pulling a thread, never by a test: the rendezvous was hashed from the CODE folder so the frozen daemon and working-tree clients computed different pipe names and never met (~12h of silence); port and host each lived as a constant in one file facing config in another; four protocol routes were constants of the daemon AND hand-written strings in four client shells. The port survived a later move untouched because it was WRITTEN; the pipe broke because it was GUESSED — that asymmetry is the whole lesson. Now: the rendezvous fingerprints the served `stateDir` (the DATA, never the code path), the listening address is one grouped config key, the routes have one owner. A misspelt route does NOT 404 — the daemon serves the gate route for any path it doesn't recognise, so a purge purges nothing and a turn goes uncounted, in silence.
- **Steering journals live outside every work tree**, resolved by `paths.js`, never a tree's own `__dirname`: both gitignored, so each worktree used to hold its own copy and they diverged (75 lines apart on the plan, 17 on the archive) — two of one morning's three reds came from that single cause.
- **A fresh worktree has no `node_modules`** — the four `ast-grep` gates cannot judge and say so; run `npm ci` first or "cannot judge" reads as "nothing to judge".
- **`~/.claude/hooks/docs/` is live and shared by every concurrent session.** Copying a whole doc over its mirror clobbers another session's in-flight paragraph (measured 2026-08-22) — replace the one paragraph you own, never `cp` the file.
- **The 2026-08-23 lock race** — the daemon's `/emit` and `/turn` routes wrote the durable class with NO lock while spawned peers wrote the same files UNDER the cross-process lock. Measured: 209 lost read-modify-writes out of 800 on one key; control with both writers locked, 0-1 of 800. Nothing was ever corrupt (tmp+rename) — what vanished is a RECORDED delivery, i.e. a document delivered twice, silently. The bigger lesson: a stale exemption CARRIED ITS OWN EXPIRY CLAUSE, in bold, and still went stale with nothing going red — an invariant whose truth depends on a fact elsewhere needs a judge that RE-READS that fact.

## The daemon ownership saga (2026-08-20 through 2026-08-23, "one state, one owner")
Sixteen frame processes had no common ground but the disk, so a FILE was made to carry a conversation between them: a lock to take turns, tmp+rename to publish, a lock-less fallback, bounded retries — every layer simulated by hand the one word an OS already does: SERIALISE. Measured (Node 22.15.1): of 68 builtin modules, ZERO expose an inter-process synchronisation primitive — the one kernel primitive JavaScript can reach is the SOCKET. Proven on three kernels (CI ubuntu+windows+macos green): 16 real processes, one `once`, delivered exactly once, no lock and zero file written; no daemon ⇒ an immediate kernel fact, never a timer; state survives a restart because the snapshot is restored BEFORE `listen`.
The daemon is a write-through CACHE, never an owner: durable keys are written THROUGH to `session-store`, so its death (dozens of times a day, by design) costs latency, never a memory. A real production defect (2026-08-21) proved it the hard way: wiring only the gate to the daemon left the daemon holding state in RAM while three other consumers (session-inject, turn-count, ctxroute-reset) kept the disk — after a compaction the daemon answered 2 bytes, skills and `once` docs never came back, no error, no badge, no red gate. Rolled back the same hour. The root cause was never "we forgot the reset": any shell could open a store itself, so a change made OUTSIDE the repository (the harness wiring) silently split one state's ownership — a rule only prose guarded stopped nobody, so the capability was REMOVED (`store-resolve.js` is now the single resolution point, `only-store-resolve-opens-a-store` forbids importing a store anywhere else).
Three-OS matrix found three real defects invisible locally in one hour: a Linux abstract address starting with a NUL byte an `argv` can't carry; macOS keeping a socket FILE after a killed daemon (cleared only by asking the kernel who answers); a builder that used to decide whether its caller lives (`createServer` threw on `EADDRINUSE` and killed the process before the bind logic could inspect a dead socket file — fixed so a core returns a verdict, the shell decides to die). Two of the three round trips were lost the first time because the failure was unobservable (a 30s timeout saying only "it timed out", stderr thrown away).
The harness wiring used to be declared 19 times BY HAND (16 gate frames + session gate + turn counter + PreCompact reset) — the lane argument was written on the 16 and forgotten on the 3, so the gate recorded in the daemon while its peers erased the state files, silently, for hours before the doctor caught it. `wiring.json` is now the single source, generated by `tools/wiring-generate.js`, never hand-edited again — behind four non-optional guards (timestamped backup, atomic write + re-read + re-parse, byte mismatch ⇒ restore, any foreign declaration ⇒ refusal).

## `keys` — the ten-defect family (2026-08-19 through 2026-08-20)
`keys` shipped 2026-08-19 with a schema, a validator, a dedicated suite, 959 green tests and 100% mutation — and FOUR real holes, none found by those tests: (1) inert on the skills' `match` dimension, 8 fleet entries out of 8 (`skillRules` rebuilds its rule field by field); (1bis, the worst) `loader.rulesOfDecl` dropped it in BOTH branches — `keys` was inert in every real doc of the corpus, working only on hand-built rules in tests; (2) a whitelist only replaced the universe for the TRIGGER, leaving `scope`/`exclude` blind — 780 divergences measured; (3) `exclude` fell back to per-candidate (existential) evaluation the moment `keys` removed the raw command from the params — 192 divergences measured, the exact ㊼ defect returning by a side door; (4) `cwd` lived outside every key universe as a hard-coded special case. Two found by behavioural probes, two by the INDEPENDENT MODEL the moment it was taught the operator — an operator outside the judges is an operator whose semantics nobody verifies.
Even fixed, `keys` still could not do the thing it was built for: a shell gesture carries THREE facts under one name (what it SAYS, where it WORKS via `cd X && …`, the paths it RECONSTRUCTS from that directory glued to every following word) — measured on 28,703 real actions, `keys: {match:["-command"]}` on the 8 fleet skills destroyed 2,281 injections of which 1,087 (47.7%) were real work. Splitting the observable in two was STILL not enough (the 10th defect, found by the maintainer the same evening watching what got injected): `-command` shut the raw text and the `cd` reconstruction reopened the window — a project name merely QUOTED after a `cd` becomes a plausible path OF that project. Measured: 13,910 shell actions, 6,336 carrying a `cd` (46%), 402,734 fabricated paths, up to 1,740 for a single command, one of which delivered a foreign project's entire 90KB skill into an unrelated session. Fixed by declaring the derived facts in a registry (`src/derived-observables.js`) rather than new fields — the fleet's entries now write `["-command","-commandPaths"]`, citing a project stops injecting it while working in it still does.
`defaults.{source}` gained the filters ONE DAY after being refused with a written reason ("the global key universe already exists") — refuted by measurement: making every doc of a category stop reading one observable meant writing it on 300+ entries, an enumeration born stale.

## Expressiveness measurement history (2026-08-14 through 2026-08-20)
"Complete for a fixed universe" was quoted as "complete" — a true theorem, a false sentence, with its own warning already written in the file. Measured, characterized twice: `language-completeness.test.js` proves the sayable set is EXACTLY `{f | f(empty action)=false}` over a fixed universe (128/256, before ㊺①: 120/256, `A∧B∧C` inexpressible) — that axis never bit again. `observable-reach-gate.test.js` closed the SECOND factor (which facts the language can even see): it found the tool NAME reachable negatively (`exclude`) but not positively by substring — an enumeration of tool families is therefore accepted, declared, and deliberately never widened without a real use case (the price would be every `scope` of the fleet widened forever). Every defect this project has ever had — ㊵, 51, ㊴, ㊽, ㊿, 53bis, `keys`, `cwd`, `commandCwd` — was a hole in WHAT THE LANGUAGE CAN SEE, never in how it combines what it sees.
