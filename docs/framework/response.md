# `response` — a doc decided AFTER the tool answered (2026-09-23)
🛑 **OFF BY DEFAULT, NOT RECOMMENDED ON CLAUDE CODE (operator decision, 2026-09-23).** `afterFrames` absent or `0` = the moment does not exist. Measured the hour it went live: 2 extra POSTs per tool call (~20-30 ms), a "2 of 2 delivered" line under every tool, for a capacity no doc used. If you turn it on, you MUST first write the doc that needs it and measure the refusal rate before and after. Codex (command lane, no frames) keeps it.
🔑 **Every other word reads what the agent SENT; `response: {"scope": [...], "exclude": [...]}` reads what the tool ANSWERED.** A SETTING in `frontmatter.settingRegistry()` (not a per-rule operator: the answer belongs to the ACTION), resolved by gate.js like `category` (entry > `defaults.{source}` > framework `null`, NO global stage). Accepted in file docs, `tool` docs, MCP docs, skills and `defaults`; refused inside a `rules` entry and in `docs/session/`.
🛑 **A WORD OF THE LANGUAGE, NEVER A KEY OF THE DATA.** Reaching the answer through `keys` was proposed and REJECTED (operator): a parameter named `response` would have collided with it. A reserved sigil (`@response`) was rejected too: it makes the collision rare, never impossible. The STRUCTURE separates them.
🛑 **ONE ACTION, TWO MOMENTS, EACH DOC IN EXACTLY ONE.** `gate.decide`'s 9th argument `after` = `{response}` once the tool answered, absent before. A doc of the other moment leaves the decision SILENTLY and FIRST (before the target filter and `category`, or an exclusion would be announced twice). After the answer: NO drift tick (the action was counted before it ran — ticking again brings every `smart` doc back at half its threshold) and NO refusal (the action already ran; the answer is content no one controls). `validate` refuses `enforce: true` + `response`.
🛑 **IF YOU SERVE THE AFTER MOMENT, YOU MUST GIVE IT ITS OWN INVOCATION** (`lib.momentInvocation` → `<tool_use_id>-after`): the harness sends the SAME `tool_use_id` on both events, and the plan, the frame sequencer and the collection memo are keyed by it — sharing it REPLAYS the before-plan, nothing new, nothing red. Seen RED on both lanes (spawn and daemon).
⚠️ **The answer's universe** (`response-pure.js`): every text at any depth, EVERY key traversed (the ㊿ `content` exclusion protects the gesture, never the answer), a JSON text read as the object/array it encodes (MEASURED: Claude Code 2.1.280 hands a structured MCP result as the STRING `{"state":"posted"}`), key names never matched, same bounds as the parameters — a crossed bound is SAID (`truncated`). The ∃/∀¬ semantics is `file.filtersRefuse`, shared, never rewritten.
⚠️ **Harness dialect = DATA** (`harness-profile.AFTER_ANSWER`: event + answer field per harness), read by `lib.afterAnswer`; the envelope is `pretool-core.afterOutput` (PostToolUse, NO decision field), shared by both shells. A harness with no such event (Windsurf, Kiro, 2026-09-23) simply never delivers these docs — a degradation, never a breakage.
⚠️ **Bandwidth apart: `afterFrames`** (config key, `framed: "afterFrames"` in `wiring.json`, judged apart by `doctor --settings`; on Codex `doctor --codex-hooks` requires `codex-doc-inject.js` in a `PostToolUse` SECTION whenever `afterFrames` is declared, since "wired anywhere" stays true once only that block is dropped). The harness POSTs its WHOLE payload, answer included, to EVERY declaration — 32 frames would ship a 100 KB answer 32 times per tool call. Keep it small; what does not fit goes to the queue.
