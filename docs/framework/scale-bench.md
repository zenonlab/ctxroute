# scale-bench.test.js: the SLOPE at the real sizing, never a millisecond
🛑 **ASSERT ON RATIOS ONLY.** A duration belongs to this machine; how the cost GROWS when the load multiplies belongs to the algorithm. Never add a threshold in ms, in bytes or in requests per second.
🔴 **THREE AXES, AND THEY ANSWER DIFFERENT QUESTIONS — never quote one for another.** **A = HELD STATE** (cells ①②, scopes 384→3072): does holding more agents' memory cost more per request? **B = CONNECTED AT ONCE** (cells ③④, 64→1024 established clients, held state FROZEN at 128 scopes): does serving ONE agent cost more because N others exist? **D = CONTENTION** (cells ⑤⑥, 4→32 writers on ONE lock, 2026-08-23): what does one critical section cost when the 32 frames of a single action dispute the same lock? **A map with 1024 entries is neither 1024 concurrent clients nor 32 writers inside one critical section.** ⚠️ `EVICT_LEVELS`/`BAR_EVICT` (axis C, eviction) are DECLARED in the file with NO cells behind them: constants, never a measurement — do not quote them.
🔴 **MARGIN A = 1.67, DERIVED FROM THE MEASURED PAIR** HEALTHY 0.89 · SABOTAGED 3.13 ⇒ √(0.89×3.13). It was 3.0 and the sabotaged store cleared it by 4 % — the gate CERTIFIED a defect. **RE-DERIVED 2026-08-25 on the redefined quantity and it came back to the SAME number**: healthy 0.83/0.91 · sabotaged 3.10/3.30 ⇒ √(0.91×3.10) = 1.68. 🔴 **A'S RANGE WAS WIDENED TO 384…3072 ON 2026-08-23 BECAUSE THE LOCK BURIED THE SIGNAL, and that is "shrink the constant", never "move the bar".** `/turn` and `/emit` now take the real cross-process lock: **421 µs per request MEASURED** (mkdir+rmdir 326 µs, parent `mkdir -p` 123 µs) where the work used to be ~3 µs, so at 128…1024 the sabotage read **1.18x against 1.67** and cell ② reddened *"certifying, not measuring"* — correctly. Fit `C + a·N`: a ≈ 165 ns/scope, i.e. the constant is worth ~2,550 scopes. Widened: **1.87 / 1.99 measured, healthy 1.06 / 1.13.** 🛑 The top is DERIVED as ¾ of `MAX_DURABLE`; the last quarter is for the `doc-seen-` scopes the `/pretool` track creates, and a cell REFUSES a run where the LRU ran (that would be eviction, not held state). ⚠️ `SOUS_LOTS` 5→9 in the same gesture: at five the same sabotage read 1.97/1.87/**1.71** — a verdict landing within 2 % of the line is a cell that will flip, then be disarmed.
🔴 **AND WIDENING WAS NOT ENOUGH EITHER — THE LOCK IS 99.9 % OF A REQUEST, MEASURED 2026-08-25.** On a quiet machine cell ① was GREEN and cell ② FAILED at **1.15x**: "certifying, not measuring". Three quantities isolated on the same store and the same address settle it: one whole `handle('/turn')` **1,267,266 ns** · `withLock` on an EMPTY critical section **1,413,648 ns** · `turnCore.bump` alone **1,254 ns**. Widening again is arithmetically closed: C ≈ 1.35 ms against a ≈ 156 ns/scope ⇒ the constant is worth **~8,600 scopes**, and clearing 1.67 would need a top level of ~5,500 — above the 4096 ceiling, where the LRU runs and the axis stops measuring held state.
✅ **SO THE LOCK IS PRICED OUTSIDE THE TIMED REGION, EXACTLY AS THE SOCKET ALREADY IS (2026-08-25), ON BOTH A AND B.** The verdict is the nanoseconds spent INSIDE the store; the clock starts inside the critical section. 🛑 **The real path is unchanged** — every timed call still goes through `hs.handle`, still takes the REAL lock at the REAL address, still writes through the real store. The lock is not removed, stubbed or shortened, and it is measured SEPARATELY by axis D, which exists for nothing else. ⚠️ **The wrapper is OUTERMOST** (the sabotage's work is INSIDE the timed region — the other way round would time the healthy store and let the defect run for free) and installed on **BOTH modes** (an instrument on one side only compares two different measurements). 🛑 **DECLARED BLIND SPOT**: a cost growing with the held state WITHOUT touching the store is invisible — bounded by `only-store-resolve-opens-a-store`, and `scopes()`/`size()` are wrapped too, so a handler walking the state through them IS seen. 📐 **RESULT, same run**: axis A healthy **0.83** vs sabotaged **3.30** (bar 1.67) · axis B healthy **0.70** vs sabotaged **4.11** (bar 2.83). 🛑 The bars were NOT moved and neither sabotage was touched.

📐 **BAR D = √(K_D) = √4 = 2.00, `Math.sqrt` OF THE LEVELS** — geometric mean of model ① (a mutual exclusion whose acquisition work ignores how many others want it ⇒ ratio 1) and model ② (a section proportional to the disputants — every home-made FIFO lock ⇒ ratio K_D). 🛑 **AXIS D GATES ON WALL TIME PER COMPLETED SECTION, AND CPU IS PRINTED BESIDE IT, ASSERTED ON BY NOTHING.** CPU looks like the purer quantity and is a TRAP: `lock.js` waits by POLLING, so the machine does ~W wake-ups per handover BY CONSTRUCTION and a perfectly correct lock is already linear in W in CPU — the healthy side read 1.28 then 2.05 against the same bar depending only on how long the phase ran. **A metric a healthy implementation cannot pass is a coin toss, not a criterion.** The CPU column PRICES that polling (~3 wasted syscalls per section at 32 disputants); it cannot judge it.
🛑 **AXIS D'S DISPUTANTS ARE REAL OS THREADS, and the substitution is axis B's, one floor down**: `mkdirSync` is atomic for the KERNEL and a synchronous fs call runs on its calling thread, so the lock cannot tell a thread from a process; 32 node processes would measure the SCHEDULER. NOT exercised by it: distinct address spaces, and a holder that DIES mid-section (`STALE_MS`, measured nowhere). Sections are shared out so every level runs the SAME count (1024), the barrier is a worker MESSAGE, and every disputant calibrates its own uncontended cost on its OWN private address.
🔴 **AND AXIS D FOUND A REAL DEFECT ON ITS FIRST RUN — `withLock` FAILS OPEN WITHOUT EVER TIMING OUT.** 32 threads on one address: **12 EPERM out of 768 acquisitions (1.6 %)** with `fs.mkdirSync` patched to record the kernel's own codes; on Windows a directory whose deletion is still pending answers EPERM, and `lock.js` treats every code but `EEXIST` as unrecoverable — it `break`s, the section never runs, the caller gets the fallback. **In production each one is a state update silently not made**, at the exact fan-out of one action. Cell ⑤ is RED on it, by name. 🛑 The fix belongs to `lock.js` (retry the transient codes); never raise the timeout, never relax the cell.
🛑 **THE NOISE FIGURE THAT GATES IS THE INTER-QUARTILE RATIO, NEVER max/min.** `nu` = the spread of the CENTRAL half (the noise of the median, the statistic actually used) and it gates; `spread` = max/min, reported and gating NOTHING — it measures the outliers the median exists to discard.
🔴 **AXIS B'S SUB-BATCH IS A FIXED 128 CALLS AGAIN SINCE 2026-08-25, AND THE PREMISE IS WHAT CHANGED.** Sizing in TIME (≥ 20 ms, calibrated by a 3-pass pilot) was right while the reading was the WALL time of a batch: at 160 calls a batch lasted under 1 ms against a ~15.6 ms quantum, so one preemption WAS the reading and the refusal flipped 1.71 → 3.35 between identical runs. A longer batch buys no protection and only wall cost. 📐 **AND IT HAD STOPPED ANSWERING: `LOT_MIN = 200` forced 270 ms per sub-batch (13× its own floor) plus 1,500 pilot calls per level ⇒ ~26 s before a socket was opened, and BOTH axis B cells hit the 30 s lane timeout.** Now ~10.5 s per cell.
