# state-entry-rebuild — A RECORD IS PROPAGATED, NEVER REBUILT BY LITERAL
🛑 **THE CLASS IS NOT "this field was forgotten". It is: REBUILDING A RECORD FIELD BY FIELD SILENTLY DROPS EVERY FIELD ABSENT FROM THE LIST.** The literal asserts *here is the whole entry now* — an assertion about fields its author never considered — and nothing goes red: the shape stays valid, the suite stays green, whatever lived in a dropped field is gone.
🔴 **PAID TWICE HERE, BOTH UNDER A COMPLETE GREEN.** ① `sources/skill.js`: `skillRules` rebuilt its rule field by field ⇒ `keys` was born INERT on 8 fleet entries out of 8, with its schema, its validator, 959 tests and 100 % mutation. ② `gate.js` (2026-08-23): the foreign-action branch rebuilt a smart doc's entry as `{ seen, sinceLastCall: n + 1 }` and dropped `denied` — the flag that carries *a block is NEVER followed by a block* — so a refused gesture was refused a SECOND time. **28 of 1,024 decisions diverged from the independent model, all one-directional, and the three conditions (`enforce` + `smart` + driftUnit `tool`) were met in production.**
⚠️ **THE CURE IS THE SPREAD, and it is structural**: `{ ...entry, field: newValue }` keeps the record's shape OPEN, so a field added tomorrow survives by CONSTRUCTION instead of being born inert. The rule clears an occurrence the moment a spread appears anywhere inside the literal — a gate must be satisfiable by the RIGHT gesture, or it teaches people to silence it.
⚠️ **SEPARATION OF POWERS, DO NOT BLUR IT**: `rules/no-rebuilt-state-entry.yml` DETECTS with **zero exemption**; `state-entry-rebuild-budget.json` + `src/state-entry-rebuild-pure.js` + `test/state-entry-rebuild-gate.test.js` carry the POLICY and the RATCHET. 🛑 No `ignores:`/`files:` in the rule — a permanent hole, sealed by a dedicated check.
📐 **THE PERIMETER WAS CHOSEN BY MEASUREMENT, and the wider readings were REFUSED WITH THEIR NUMBERS (204 tracked files)**: any spread-less literal reading a member = **404 hits** (a projection is legitimate and dominant — unusable, and a noisy gate gets unplugged, which is worse than none) · restricted to the right-hand side of ANY assignment = **3 hits, 3 false** (`module.exports = { … }` among them) · restricted to a **SLOT WRITE** = **0 on the repaired repo, exactly 1 on the defect restored**. A cell pins the two refused readings, so widening turns red instead of flooding.
⚠️ **IT TARGETS DERIVATION, NEVER CREATION**: `next[doc] = { seen: true, sinceLastCall: 0, turn: turnCount }` reads no existing value, so nothing can be lost and it is not matched. That exemption is what keeps the gate quiet on the most common correct shape here.
⚠️ **`field: left` IS LOAD-BEARING in the rule**: without it the assignment's LEFT side counts as "reads an existing value" (`acc.meta[m.doc]` is itself a member expression) and a plain fresh write matches — the first version did exactly that, 2 false positives out of 2.
⚠️ **DECLARED BLIND SPOT, written rather than hidden**: the `skillRules` half (a FRESH `const rule = { pattern, doc }` built from a source object) is NOT reachable by AST — syntactically identical to the 404 legitimate projections.
