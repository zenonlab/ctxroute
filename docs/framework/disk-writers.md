# disk-writers.json — SPACE DECLARES ITSELF (2026-08-21)
🛑 **ANYTHING THAT WRITES DECLARES ITS CEILING AND ITS EVICTION IN THE SAME GESTURE AS ITS CREATION.** Disk is FINITE and this machine runs 24/7 for YEARS with no operator: without a ceiling the component DOES NOT EXIST — an ARCHITECTURE bug, never an operations one. The question is never "is it big?" but "at 10 years, how much is this worth?"; monotonic growth is a DATED outage and "we will purge later" puts a human back inside the loop.
⚠️ **TRAP ①: A THRESHOLD PROBE IS NOT AN EVICTION** — it CONSTATES, and by then it is too late. Alert on the SLOPE, evict by age or by tier. **TRAP ②: AN EVICTION IS PROVEN BY WHAT IT DELETES** — a real fleet script targeted `*.tar.gz` while the producer wrote `*.sql.gz`: 0 bytes removed since forever, disk at 87 %. A cleaner that matches nothing is indistinguishable from a cleaner that works.
🔴 **A DETECTOR KEYED ON A RECEIVER NAME IS BLIND TO ALIASES, AND IT GOES BLIND IN SILENCE — MEASURED 2026-08-21**: `require("fs").writeFileSync(…)` and `const fsSab = require('fs'); fsSab.writeFileSync(…)` both left this gate GREEN. An unmatched form is NOT "an undeclared writer that goes red": it is a writer NOBODY SEES, i.e. fail-OPEN. ⇒ **Key on the METHOD, never on the receiver** (`writeFileSync` is distinctive on its own), and GENERATE those atoms from the manifest's `write` entries so the detector cannot drift from the policy. Never write a blind cell as if it failed closed — that tells the next reader the case is handled.
⚠️ **TWO FAMILIES, NEITHER REPLACES THE OTHER**: `rules/fs-call.yml` is RECEIVER-anchored and is the only half that matches an UNKNOWN method name, which is what forces every `fs` method met to be CLASSIFIED (the write set stays DERIVED, never a hand list that only knows the past); the METHOD-anchored half is generated at gate time and kills the alias, double-quote and destructured-import classes. `openSync` is FAIL-CLOSED as `write` (its flags are a runtime value the AST cannot decide). **AST, never regex** — these files carry "NEVER a direct `writeFileSync`" in comments, and a regex would accuse the documentation that protects the invariant.
⚠️ **SEPARATION OF POWERS**: the rules DETECT with **no exemption whatsoever**; `disk-writers.json` + `test/disk-writers-gate.test.js` carry the POLICY and the RATCHET, in BOTH directions — an undeclared writer is held at ZERO, a declaration whose writes vanished is a DORMANT PERMIT that gets re-inherited, budget included.
