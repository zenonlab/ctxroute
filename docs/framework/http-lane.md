# http-server.js — the SAME gate, served over a socket. NOT WIRED (2026-08-20).
🛑 **INERT ON PURPOSE.** No `settings.json` entry points here; nothing spawns it. Switching over is the maintainer's explicit decision, taken when no agent is running. Until then its only job is to be PROVEN identical to the spawn lane.
📐 **MEASURED FACTS, 2026-08-20 — do NOT re-research this.** Claude Code **2.1.237**: `type:"http"` is real, verified IN the installed binary (literals `"HTTP hook type"`, `url` = *"URL to POST the hook input JSON to"*, plus `if`/`timeout`/`headers`); five handler types exist (`command`·`http`·`mcp_tool`·`prompt`·`agent`); *"All matching hooks run in parallel"*; output cap **10,000 c per OUTPUT**. Codex **0.146.0**: *"Only `type:"command"` handlers run today"* — `prompt`/`agent` parsed and skipped, **no http**. Sources: `code.claude.com/docs/en/hooks`, `learn.chatgpt.com/docs/hooks`.
🛑 **THE CAP IS PER OUTPUT, NOT PER PROCESS ⇒ N DECLARATIONS ARE STILL REQUIRED.** HTTP changes their PRICE (~330 ms of node startup each → one local POST), never their NUMBER. Collapsing to one declaration would drop an action's capacity to a single frame and make the agent act on partial knowledge.
🛑 **KEEP `lock.js`.** "One daemon, therefore no lock" is the trap: Codex keeps spawning real processes against the same state files, and other sessions exist.
🛑 **THIS PATH MUST STAY SYNCHRONOUS.** `lock.js` busy-waits and assumed every caller was a short-lived process. Here N frames land in ONE process: an async core would let request A hold the lock while B spins on it for the full timeout — a self-deadlock that looks like a slow daemon, not a bug.
🛑 **NO `deadline.arm()` here** — deliberate inversion of the rule every other shell follows. The deadline kills zombie hook PROCESSES; a daemon is supposed to outlive its request. The bound belongs to the harness `timeout`.
⚠️ **Loopback only, and the dialect is NOT reimplemented**: the response JSON comes from `doc-inject.output()`, the very function the spawn lane uses — a second copy would be a twin that drifts.
🛑 **A DAEMON HOLDS ITS CODE IN MEMORY — the defect a spawned hook CANNOT have.** After a `git pull` it looks perfectly healthy and serves yesterday's logic: a GREEN THAT LIES, the exact thing this repo fears most. Guard = `watchOwnCode`: the kernel TELLS us a file changed (inotify · ReadDirectoryChangesW · FSEvents), we exit, the OS restarts. Zero polling, zero hashing, zero "am I still current?".
🛑 **WE WATCH DIRECTORIES, NOT FILES, AND IT IS MEASURED.** Git renames over the target instead of writing in place, so a file watch follows the dead inode and goes SILENTLY deaf — worse than no watch. `http-daemon-lifecycle.test.js` ② performs that exact rename on the real kernel. The watched set is DERIVED from `require.cache` (a file added tomorrow watches itself), `node_modules` excluded.
🛑 **EXIT CODE NON-ZERO (`75`), for portability not style**: a supervisor only restarts on FAILURE (`Restart=on-failure` · launchd `KeepAlive` · Task Scheduler `RestartOnFailure`). `exit 0` reads as "job done" and Windows would never bring the service back.
📐 **MEASURED 2026-08-20 on the real corpus — and it moves the target.** Round trip **41.49 ms**, engine alone **41.32 ms** ⇒ **the transport costs 0.17 ms**. The 41 ms are the corpus re-read, which the spawn lane pays too (hidden inside node's startup). ⇒ the daemon alone takes an action from ~5.3 s to ~660 ms (16 frames served one after another); the REST of the win needs an in-memory corpus, invalidated by the same watch — a decision, not a detail, and the differential must stay byte-identical.
📐 **NO LEAK, PROVEN BY THE SLOPE, NEVER BY A CEILING.** Ten equal batches, bytes retained per request: **370 → 281 → 181 → 150 → 134 → −1 → 18 → 65 → 50 → −12** — it converges to zero, and the state on disk stays at **0 KB**. A ceiling answers "is it big on THIS machine today"; only the slope answers "does it keep growing", the only question for a process running for months. The gate carries its own SEEN RED: the identical criterion must REJECT a server retaining one object per request.
🛑 **AND THE FIRST VERSION OF THAT GATE WAS A CLIFF — red CI, 2026-08-20.** It compared batch 4 to batch 1 with `< half`; a loaded Windows runner read 361 → 229 → 180 → 184 KB, converging exactly as expected and rejected by four kilobytes. ⇒ **six batches, not four** (the marginal is still 150 B/req at batch 4 and only settles from batch 5), and **averages of head vs tail**, never single readings. A gate that reddens on scheduling noise is a gate people stop reading, then disarm.
⚠️ **NOTHING HERE INFERS LIVENESS.** No health probe, no heartbeat, no timeout used as a verdict. A dead socket answers `ECONNREFUSED` instantly; the service's death is an OS EVENT. 🛑 The hook must NEVER start the daemon: that is how orphans are born, and it is the OS's job.
⚠️ **ONE GUESS REMAINS, DECLARED**: what an EMPTY answer means over HTTP. We send `{}`; the doc says the endpoint answers in the command-hook JSON format but never defines silence. The equivalence lives in ONE place (`normalize()` in the differential) — measure it on a throwaway wiring before switching over, then correct that single line.
