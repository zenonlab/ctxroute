# dual-transport.test.js — ONE handler, TWO addresses, ONE store

🔴 **BEFORE 2026-08-21 THE KERNEL LANE HAD NO OTHER END.** The daemon bound ONLY the TCP port while `state-client.js` connected on `endpoint()`: **nobody was listening where the client knocks**, so switching the shells over would have sent every frame to `ENOENT`, hence to the local state-less path, hence `once` WITHHELD on every action. 🛑 **The three-OS proof could not see it**: `state-daemon.test.js` forks its OWN test daemon, never this shell — it proves the MECHANISM. **A green on a twin is not a green on the thing**, and that is the lesson to carry, not the fix.
⚠️ **BOTH ADDRESSES ARE LEGITIMATE, neither is a mistake.** The PORT serves Claude Code's native `type:"http"` handler — it takes a URL, and a pipe is not one. The RENDEZVOUS serves the client lane: spawned hooks, and Codex, which has no `http` handler at all.
🛑 **ONE `store` FOR BOTH, DELIBERATELY** — two would be the "two memories" defect `client-lane.md` forbids, reintroduced from inside the daemon. And ONE protocol: a second dialect would drift from the first.
⚠️ **`kernel-bind` TAKES THE SECOND ADDRESS, NEVER A BARE `listen`.** On macOS a killed daemon leaves its socket FILE behind, and the entry is cleared only after ASKING THE KERNEL who answers — never on "the file exists so it is probably dead", which would delete a LIVING daemon's socket and leave every client knocking on an address nobody owns.
🛑 **WHAT THIS SUITE MUST KEEP PROVING**: the same server on both addresses, byte-for-byte equality of the answers, an anti-vacuity floor, and it has been **SEEN RED with a single listener**. A cell that cannot fail when one transport disappears certifies instead of protecting.
