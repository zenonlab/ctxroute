# personal-leak — the gate that stops personal data from reaching a PUBLIC repo
🔴 **THE ROOT IS MEASURED, NEVER SUPPOSED — this gate scanned a QUARTER of the repo for weeks (found 2026-08-20).** `ICI` was `path.dirname(import.meta.url)`, i.e. the `test/` FOLDER, and `git ls-files` run from there lists only what is under it: **86 files instead of 229**. The repo's ONLY blocking gate, born from a real leak, was blind to `src/`, to the root and to `docs/` — and its anti-vacuity floor (">50") passed comfortably on the 86, so nothing screamed. 🛑 A gate that measures a SUBSET is indistinguishable from one that measures everything. Root now comes from `git rev-parse --show-toplevel`, floor raised to the real perimeter (>200) so shrinking the scan reddens at once. ⚠️ Proven by a real decoy: a tracked file carrying the maintainer's home path is now NAMED, exit 1 — it passed silently before. ⚠️ Re-scan after the fix: 229 files, ZERO real leak was sleeping in the 143 never read.

⚠️ **PUSHED DATA CANNOT BE TAKEN BACK**: it survives in `git log -p` even after the tree is fixed. Observed 2026-08-04 — 5 leaks in tracked files (fixed BY HAND, without a net) + the user config becoming tracked because a codemod had missed `.gitignore`.
⚠️ **NO PERSONAL DATA IN THESE FILES, BY CONSTRUCTION**: a gate hard-listing the first name or the clients WOULD ITSELF BE THE LEAK. Everything comes from outside — environment (OS account, personal folder) + the private list `~/.claude/secrets/ctxroute-fuite.json`, outside the repo. Writing a string to protect there = cancelling the gate.
⚠️ **DERIVE, NEVER LIST**: clients come from the FOLDERS carrying their marker (`brief.md`), not from a written list — a list would be stale at the next client and would protect less SILENTLY. The marker also rules out `.git`/`node_modules`/`scripts` (measured: 4 collisions, 3 false).
⚠️ **DERIVING FROM A SINGLE ROOT = A BLIND SPOT (REAL leak, 2026-08-10)**: the list derived ONLY from SEO clients ⇒ the name AND email of a **social** client slept in `REFACTOR-PLAN.md`, TRACKED, gate GREEN. **Part ②: every root SEEN on disk must be DECIDED** — `derivedFolders` (with its marker) or `ignoredRoots` (with its reason), otherwise RED. 🛑 Adding the missing root by hand closed NOTHING: the next one would be forgotten the same way. It bit on the 1st run by finding a **3rd** root (a backup carrying 2 clients absent from the current folder).
🛑 **THE GATE WAS RIGHT — IT HAD SIMPLY NEVER RUN.** The email was detectable by the GENERIC pattern (measured: it goes red with no private list at all), but nothing triggers this test between writing and pushing. Hence `.githooks/pre-commit`: **the repo's only blocking gate** (~0.9 s), and the ONLY possible place for the "client names" half — CI necessarily runs in generic mode, private terms do not travel in a public repo.
⚠️ **WORD BOUNDARIES, never substrings**: a short first name is a sub-word of common words (2 real false positives on 08-04). And from the personal folder we keep ONLY the last segment — "Users" is generic and would make the gate red everywhere (6 false positives).
⚠️ **MUST STAY GREEN ON A CLEAN CLONE**: private list absent ⇒ GENERIC mode (real email, CGNAT/Tailscale block IP), never a failure. Documentation ranges (RFC 5737) and `example.`/`test.` (RFC 2606) stay ALLOWED — banning them would make the doctrine unusable.
⚠️ **TEXT, NOT AST**: here a name in a comment or a string IS the leak, and most leaks lived in `.md` files. AST (good for `setTimeout`) would be blind exactly where it really leaks.
⚠️ **`leak-list.js` = SINGLE SOURCE of "which terms to protect?" (2026-08-16)**: declared + derived − `exceptions` (derived terms that are NOT personal data — real case: the BRAND has a client folder, it went red on healthy content). Consumed by the test AND by the pre-commit launchers of chat-mcp/scheduler-mcp (ctxroute path resolved from HOME) — re-inlining it = a twin, and it diverged the same day. 🛑 An exception REMOVES a protection: never a client.
⚠️ **THE ADDRESS OF THE PRIVATE LIST IS OWNED BY `paths.js`, NOT BY `leak-list.js` (2026-08-22)**: `secretsDir()` REACHES it (absolute, `CTXROUTE_SECRETS_DIR`), `privateListLabel()` PUBLISHES it (`.claude/secrets/ctxroute-fuite.json` — relative, POSIX, home-free, override-proof). Until then this module rebuilt `~/.claude/secrets` from `os.homedir()`, a fourth hand-built harness root, and the note calling that omission deliberate was itself the exemption. 🛑 NEVER print the ABSOLUTE form into a doc, a message or any tracked file: it carries the real home AND names the secret store, in a PUBLIC repo whose only irreversible damage is a push. Whoever must SAY where the list goes uses the label — this very line is judged against it by `fleet-hooks-path.test.js` cell ⑬.
⚠️ **②ter STRICT SCHEMA (2026-08-16)**: the private list has a CLOSED vocabulary (`terms`/`derivedFolders`/`ignoredRoots`/`exceptions`, entries `root`/`marker`, `_`-prefixed comments free) — any unknown key is RED. Paid the same day: `dossiersDerives` left over from a rename ⇒ zero client derived, green gate (aspect ② scans zones DERIVED from `derivedFolders` itself, hence green by vacuity on an empty field).
⚠️ **A SYSTEM/CI ACCOUNT IS NOT AN IDENTITY**: on GitHub Actions the account is called `runner` — derived as-is it matched "test runner", "tap-runner", "commandRunner" ⇒ **13 false positives, CI RED on the first push**. Generic accounts (`runner`, `root`, `user`, `build`, `ubuntu`…) are RULED OUT whatever their origin. Corollary: **a term derived from the environment can be a common word on ANOTHER machine** — check it on CI, never only locally.
